# 源码审核与硬补丁清理（2026-10-06）

用户要求停止压测，审核整个源码并清理限制模型工作方式的硬补丁。本轮不请求真实模型，不启动 NOC/RTS，不启动隔离 VM，不更新 tag 或 Release。审核基线为 main `2734706c577bcf51485bac34d6351c964e32227d`；用户已有 `output/` 不纳入修改或提交。

## 审核范围与方法

对全部跟踪文件建立清单，扫描 Python、TypeScript、脚本、内嵌提示词、配置和文档引用；全部 Python 文件做语法解析，前端做测试和生产构建。逐项核对模型特判、固定次数、重复调用抑制、完成门禁、源码变化判定、Provider 配置替换和静态未使用诊断。重点沿 HTTP/WS → 会话与任务 → SSOT/QueryLoop → ToolRuntime/Client → schema/manifest/policy → 领域处理器，以及编码委派 → 候选检查 → 独立 QA → 事务整合的调用链检查。

覆盖 agent、core、backend、extensions、frontend、storage、artifacts、jobs、desktop_app、workflows、observability、evaluation、prompts、scripts、启动/打包脚本及 harness。整体扫描不等于逐行证明所有代码无缺陷；没有证据的代码不按名称或单次模型失败删除。

## 清理结果

| 原规则 | 处理后的行为 |
| --- | --- |
| 连续 12 轮源码摘要不变就检查、催促或中断实现 | 删除计数器、摘要回调及恢复状态。模型工作期间不靠源码差异决定下一步。 |
| 完成检查失败后要求下一条必须调用工具纠错 | 模型主动结束时记录真实检查及其最终报告，failed/unknown 保持真实失败或未知；协调者据证据处理后续工作。 |
| 连续两条无新工具动作的最终回复视为空转 | 删除计数终止及强制纠错提示。 |
| 连续三个 no-op 或相同错误批次中断任务 | 删除次数终止。明确取消、资源预算和工具/协议边界仍有效。 |
| 抑制重复的已知调用，再按重复签名结束；绘图另设特殊放行 | 删除抑制及绘图特殊分支。实际工具调用继续受同一治理入口控制。 |
| 网络对话含“继续”“configure”“请确认”等词便强制继续操作 | 删除文字关键词门禁。保留领域工具的实际执行、未发送命令和未知结果证据。 |
| QA 最终文字必须为固定 JSON，三次不符即中断 | 通过原生 `agent.review` 保存裁决；最终文字自由表达，不推断自然语言里的 PASS。 |
| 修订必须修改源码摘要或恢复先前失败的检查 | 删除差异门禁。相同源码也必须完成准确检查和新的独立 QA；有差异也不代表通过。 |
| YAML 显式选择 MiniMax-M1 被静默替换成 M3 | 保留显式模型选择。默认配置与真实协议能力限制分开。 |
| 上述机制留下的配置、回调、缓存声明、私有函数与测试 | 删除死路径；旧行为专属测试改为重复调用、长序列、实际检查、身份和协议完整性回归。 |

业务验收器的 NOC/RTS 功能断言没有减少。团队验收删除的仅是“源码必须变化”的框架判据；仍核对准确候选、独立 QA、实际检查、真实发布 journal 和完整源码树。过去压测报告及失败证据保持原样，历史 PASS/FAIL 不因本次清理重写。

## 调用身份修复

完整 QueryLoop → ToolRuntime → ToolRuntimeClient 回归发现：内层客户端使用实际 `subagent`，外层执行器缺少身份投影时默认使用 `turn_runner`。现在 SSOT 从服务端 `requested_by` 绑定 `caller_type`，请求 metadata 不能覆盖两者，所有工具共用这个身份投影。

`agent.review` 使用现有 registry、schema、manifest、policy、脱敏及审计通道，专用 manifest 仅允许 subagent，保持 `agent.manage` 的既有 caller 限制。提交还需活动只读 QA 环境与准确会话绑定，不能由父任务、实现者、其他会话或关闭环境代交；模型提供的候选摘要/子任务 ID 被服务端绑定替换。它只记录判断，不写源码、不整合。缺少裁决、明确阻断、执行未知和源码不符仍不能整合。旧调用方的完整 v1 JSON 最终回复可读取兼容，新 QA 无须采用它。
