# 联智中枢整体审查与修复记录

日期：2026-10-01。基线：`main` / `5c8a6a8`，版本 `3.2.4`。按本轮用户要求，不部署服务器或重启现有服务；后续用户要求更新 Windows Release，发布版本为 `3.2.5`。

## 审查范围

检查了认证与工作区隔离、模型编排、工具治理网关、外部写入与审批恢复、作业、存储、扩展、网络设备与拓扑、前端认证及事件传输，以及构建、测试和部署配置。采用代码检查、调用链追踪、回归用例和仓库原有 Chromium E2E。Code Review 插件当前暴露的接口用于 PR CI 检查，本轮没有借该接口执行本地源码审查。

此记录描述本轮确认并修复的问题，不代表每个源码分支、真实设备和生产环境都已验证。

## 已修复的问题

| 级别 | 触发与原行为 | 修复位置与结果 |
| --- | --- | --- |
| P1 | 使用可解析的连接 ID 后缀时，设备工具能执行，审批却因与完整 ID 比较不匹配而跳过。 | `extensions/approval/service.py`：先解析 canonical ID，再核对当前 Skill 和已选连接范围。 |
| P1 | 选择 Skill 后开启审批，运行时仍读取选择时的关闭快照，配置调用绕过审批；反向切换也会保留旧要求。 | 同上：调用时读取已发布 Skill 的当前开关和范围。 |
| P1 | 拦截器发现或审批钩子异常被吞掉，后续真实写入照常执行。 | `core/runtime_engine/execution_interceptors.py`、`query_loop.py`：返回未执行的结构化错误，禁止继续调用 handler，不泄露原始异常。 |
| P2 | 决策请求可通过 `decided_by` 伪造审批记录中的身份。 | `extensions/approval/backend.py`：身份来自服务端认证主体；本地无认证主体时使用 `user`。 |
| P2 | 拓扑调用在编排层和执行网关中被整体豁免 schema 错误，错误参数可以进入 handler。 | `core/tools/executor.py`、`core/runtime_engine/query_loop.py`：删除豁免；合法自然别名、额外字段和字符串版本继续支持。 |
| P2 | 编排层只检查数组中的字符串或 `oneOf` 元素，普通对象数组的错误元素仍被当成合法计划。 | `core/runtime_engine/semantic_validator.py`：对所有非空元素 schema 共用执行网关的递归校验。 |
| P2 | 拓扑成功 patch 的输出没有 `action`，绘图完成门禁无法识别真实成功，可能要求重复绘制。 | `extensions/network_operations/backend.py`：成功结果返回实际 `read` / `patch`。 |
| P2 | 未填 action 且只删除分组或图元时，被推断为读取，返回成功但未删除。 | 编排层和拓扑工具均补全删除字段判断；测试核对实际保存结果和其他节点保留。 |
| P2 | schema 声明的 `title` / `summary` / `comment` 被接受，却不保存到标题与描述。 | 拓扑工具映射到 canonical 字段；显式 canonical 值优先，清空描述也可识别为修改。 |
| P2 | fetch SSE 的 CRLF 跨网络分片时被转换为额外空行，同一事件错误拆分并丢失事件名或完整内容。 | `frontend/src/api/sse.ts`：跨分片跟踪 CR，保留命名事件、多行内容和事件 ID。 |
| P2 | Cookie 登录部署明确禁用本地令牌后，每次 API 调用仍重新请求 `/api/local-token`；并发调用也各自探测。 | `frontend/src/api/client.ts`：共享在途请求，缓存明确的 `local_token_unused`；临时故障仍可重试。 |
| P2 | 流式函数名分片被覆盖，`network__operations__topology` 最终变成 `topology`；早于函数名到达的调用 ID 也会丢失。 | `agent/llm/provider.py`：拼接函数名分片，支持已发布完整名称的重复快照，独立保留 ID。 |
| P2 | 损坏、截断或非对象 JSON 参数被换成 `{}`，拓扑随后把它误判为读取，画布仍为空；Anthropic 非流式路径还可能抛出类型转换异常。 | Provider 四条接收路径共用参数解码，保留结构化校验错误，禁止以空参数掩盖传输故障。 |
| P2 | 流式响应中缺少函数名的工具提议被直接丢掉，编排无法反馈真正的失败原因。 | 保留提议的 ID、参数和空名称，交由现有工具身份校验反馈；不执行未知工具。 |
| P2 | 原生工具参数输出截断后，继续指令只要求接续正文，模型可能继续半段 JSON 或反复宣称提交。 | QueryLoop 区分正文与工具调用的截断，明确未执行事实，要求重新发出完整原生调用，允许合同内的较小独立调用。 |
| P2 | 前端锁定的 Axios 1.19.0 被新发布的安全公告覆盖，GitHub CI 的依赖审计阻止测试和构建继续。 | `frontend/package.json`、`package-lock.json`：升级 Axios 至 1.20.0，不批量更新其他依赖；审计恢复为 0 个漏洞。 |

保留已有产品语义：审批仍为 Skill 的可选开关；设备账号决定命令最终权限；外部写入未知不自动重放；拓扑增量 patch 保留自动版本对齐；直接保存仍检测版本冲突；硬删除语义未变。

## Windows 重复 patch 的补充复现

用户提供的截图中，图纸保持 `version=1、0 节点、0 链路`，模型阶段连续宣称再次提交 21 节点和 30 链路。用户说明使用的是 review 前代码。本轮在该代码的 Provider 接收路径复现了函数名覆盖、损坏参数误变读取、无名称调用被丢弃等故障；这与截图吻合，但没有读取那台 Windows 机器的原始会话 trace，不能据截图确定该会话使用了哪一种传输故障。

新增回归测试经 Provider 接收端、QueryLoop、工具治理网关和真实图纸存储，核对 21 个节点、30 条链路、版本递增一次、patch 仅执行一次。正常流式调用用 2 轮模型调用完成；先发生输出截断时用 3 轮完成，部分调用未执行。保留已有阶段历史，不以隐藏阶段增长替代修复调用链。

## 实时链路工作区修复与 v3.2.6

本轮在 `2e1f5ad` 的工作区改动上修复了审核确认的 11 个问题：前端构建失败；终态在并发 token 之前分配序号；持久化游标越过未缓存文本；其他请求帧误投给唯一活跃回合；退出登录后自动重连和旧身份回写；共享日志缓存导致跨进程序号重复；Redis 广播丢失存储主体；幂等重定向把伪终态写入真实回合；刷新恢复遗漏工具卡、阶段输出与结果元数据；空闲应用没有系统订阅；请求 ID 清理和截断造成日志路径碰撞。

连接归应用所有，页面只订阅。新回合和恢复回合共用 reducer。游标与完整公开缓冲及标签过滤状态一起保存；遇到序号缺口只续流，不重新执行。图纸保存广播版本提示；当前已保存画布采纳更新，本地有未保存改动时只提示。未知续流目标不启动订阅 worker，同一连接的重复续流替换旧订阅。Windows 发布流程增加 Python 3.12/3.13 下的跨进程文件锁及 WebSocket 回归测试。

本地验证：后端全量 1705 passed、8 skipped；前端全量 334 passed；构建、类型检查、Ruff 和文档一致性通过。浏览器验证使用隔离服务和测试数据；新增场景覆盖跨页保留连接、刷新按游标恢复、空闲画布版本广播。本轮同步范围为 GitHub 提交推送与 Windows Release，不部署服务器，不重启现有服务。

发布后 CI 的未知写入结果浏览器用例暴露旧模拟帧未携带请求 ID；补齐与真实后端一致的 `client_request_id` 和独立终态序号，保留未知写入结果提示及禁止自动重试的断言。此补充仅修改测试契约，v3.2.6 发布包的运行时代码不变。
