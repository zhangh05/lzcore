01执行摘要

先给结论：引擎层选对了，产品层还没跟上。

换到 Cytoscape（f14b052）+ 接入 NetOps 真实设备图标集（74aa078）+ 图纸/资产解耦（bbdabdc）这三步都走对了方向——画布已经从「玩具」变成「像样的图」。但运行时实测暴露出的问题是交互层的，不是渲染层的：核心导航手势失效、双套命中逻辑并存、编辑后全量重建图元。这些在 6 个节点的演示拓扑上看不出来，在 200 个节点的真实拓扑上会放大成「不好用」。

另一层的差距是企业级能力缺位：没有导出、没有鹰眼、没有画布内搜索、没有右键菜单、没有快捷键体系，而设备/链路的真实状态没有上画布——拓扑图在网管产品里的核心价值就是「一眼看到哪里出问题」，现在这一环是断的。

03实测缺陷（P0）

以下均在 http://127.0.0.1:5273/topology 用 Playwright 实测复现，附原始输出。

P0-1

选择模式 / 连线模式下滚轮缩放完全失效

最高优先

用户打开页面默认就是「选择」模式，此时滚鼠标滚轮没有任何反应。这是画布最基础的两个导航手势之一（另一个是平移），失效等于把用户锁死在初始视口里，只能靠右下角的 +/− 按钮。

根因
Cytoscape 3.28 的滚轮处理器把缩放与平移开关耦合在一起。源码条件：
if (panningEnabled() && userPanningEnabled() && zoomingEnabled() && userZoomingEnabled())
而 NetOpsCanvas.tsx:234 写的是 cy.userPanningEnabled(layoutEditing) —— 只有「移动布局」模式为 true。于是缩放被平移开关一起关掉了。
附带
初始化参数 userWheelEnabled: true（NetOpsCanvas.tsx:126）不是 Cytoscape 3.28 的合法选项（全量构建里 0 命中），是无效配置，给人「已经开了滚轮」的错觉。
修复
把平移与缩放解耦：userPanningEnabled(true) 常开，用「Shift 才启用框选覆盖层」来避免抢手势（详见 P0-2）。同时删掉 userWheelEnabled 这个无效项，改设 wheelSensitivity。
实测输出：选择模式(层在) 滚轮: 131% -> 131% 选择模式(层已删) 滚轮: 131% -> 131% ← 排除覆盖层嫌疑 直接派发 wheel 到 .netops-cytoscape: 131% -> 131% 连线模式 滚轮x3: 131% -> 131% 移动布局模式 滚轮x3: 131% -> 400% ← 只有这个模式能用
P0-2

手势层全表面覆盖 + 自建命中测试，形成双选中路径

.netops-selection-gesture-layer 是一个 position:absolute; inset:0; z-index:6 的透明层，在「选择」模式下盖住整个画布，并且没有 pointer-events:none。它自己用 canvasObjectAt()（约 90 行）重新实现了一遍节点/图元/链路的命中判断——而 Cytoscape 本身就有精确的命中测试。

后果
① Cytoscape 在「选择」模式下收不到任何鼠标事件，原生能力（hover、光标反馈、框选、滚轮）全被旁路；② 命中逻辑与渲染逻辑两份，节点尺寸在 NetOpsCanvas.tsx:357 硬编码为 <=48 / <=40，与样式里的 width:94 height:76 靠人工保持同步，改样式就会悄悄失准；③ 代码里已经出现 ignoreBoxSelectionTapRef、window.setTimeout(...,0) 之类的时序补丁，这是双路径不同步的典型症状。
修复
覆盖层默认 pointer-events:none，仅在按住 Shift 时切为 auto。这样：常规操作全部走 Cytoscape 原生（hover / 点击 / 平移 / 滚轮 / 框选），Shift+拖走自建框选。既能保住现有框选手感，又能一次性修复滚轮缩放，并删掉 ~90 行重复命中逻辑。
实测：顶层元素(画布中心): netops-selection-gesture-layer getComputedStyle -> z-index: 6, pointer-events: auto
P0-3

框选之后没有任何视觉反馈

canvas-mode-hint 在「选择」模式下是写死的静态文案「普通单击选择对象；直接在空白处按住鼠标拖框多选」。用户拖完一个框，画布上看不到选中高亮的计数，文案也不变——不知道自己选了几个。只有切到「移动布局」模式才会显示「已选 N 个对象」。

修复
把「已选 N 个对象」提升为常驻状态（与模式无关），并在 N>0 时激活对齐/批量操作按钮。对标 Figma：选中后面板即时反映选中数与可执行操作。
实测：全框选后 caption: 「2 个节点 · 1 条连接 普通单击选择对象；直接在空白处按住鼠标拖框多选 接口标签」 ↑ 框选了整张画布，文案与选中数均无变化
P0-4

每次编辑都销毁并重建全部图元

NetOpsCanvas.tsx:275 的同步 effect 依赖 [props.topology]，每次 pushState 都执行 cy.elements().remove(); cy.add(elements)。也就是说：拖完一个节点松手的瞬间，整张图被推倒重画一遍。6 个节点无感，200 个节点会掉帧，且 Cytoscape 内部的选中态、动画、布局缓存一并丢失。

修复
改为增量 diff：按 id 比对 add / remove / 更新 data / 更新 position。拖拽场景甚至可以只更新 position 不入历史。这是从「能用」到「大图也能用」的分水岭。

05优化点解析

按 P0（必修缺陷）→ P1（企业核心能力）→ P2（体验精修）→ P3（差异化）排列。每项给出：现状 → 问题 → 对标 → 方案。

P0 · 必修缺陷

P0

解耦平移与缩放，修复滚轮导航

见 03 / P0-1·2
方案
① userPanningEnabled(true) 常开；② 手势覆盖层默认 pointer-events:none，Shift 按下时启用；③ 删除无效项 userWheelEnabled；④ 设 wheelSensitivity: 0.25。
为什么
Cytoscape 默认 wheelSensitivity: 1 时，滚轮一档 deltaY=100 的缩放倍率是 10^(100/250) ≈ 2.5 倍——实测三档直接顶到 400% 上限。0.25 时约 1.26 倍/档，接近 Figma 手感。
成本
约 0.5 天。收益：最高——这是「打开就想用」和「打开就想关」的区别。

P1 · 企业级核心能力（决定能否进生产环境）

P1-1

把真实状态画到画布上，并配图例

最高业务价值

现状：节点颜色只按厂商分（华为蓝 / 其他青），链路颜色按 status: up|down|unknown——但这个 status 是人工标注的图纸状态，不是实时探测结果。状态栏那句「链路颜色：图纸连接 · 管理访问状态见设备详情」恰恰暴露了问题。

问题：企业用户看到红/绿链路的第一反应是「这条链路通/断」。现在是人工标注，会造成误判；而真正采集到的数据（topologyState.nodes[].connections[].verified、observation.completeness、健康巡检脚本的 CPU/内存/日志告警）明明已经拉回来了，却只躺在右侧检视器里。

对标：Zabbix Map 的元素颜色 = 触发器状态；DNA Center 拓扑直接用健康分着色并叠加告警计数。这是网管拓扑图的存在理由。

方案
① 区分「图纸状态」与「运行态」两种语义：图纸态用线型（实线/虚线）表达，运行态用颜色表达；② 节点按采集结果加状态环（在线/不可达/未采集），与厂商配色叠加而非冲突；③ 画布角落常驻图例；④ 状态数据已有 10 秒轮询，接进画布即可。
成本
约 2–3 天（含后端 /state 增补健康摘要）。
P1-2

导出：PNG / SVG / PDF

企业刚需

现状：完全没有导出。问题：拓扑图最终要进巡检报告、变更方案、工单附件、汇报 PPT，用户只能截图——截图会截断、会带 UI 噪点。这是「做完图用不出去」的断点。

对标：draw.io 支持 PNG/SVG/PDF/XML/VSDX；Figma 一键导出多倍图。

方案
Cytoscape 原生 cy.png({ full:true, scale:2, bg:'#fff' }) / cy.svg() 即可，几乎零成本。放进「更多」→ 导出，或做成工具条图标。建议同时提供「导出当前视口 / 导出整图」两个选项。
成本
约 0.5 天，投入产出比最高的一项。
P1-3

鹰眼缩略图（Minimap）

CSS 已预留

现状：TopologyStudio.css:106 有 .topology-minimap-custom 样式、:175 有移动端隐藏规则，但代码里没有任何 minimap 实现——是 React Flow 时代的遗留。

方案
Cytoscape 有官方 cytoscape-navigator 扩展；或自绘一个 160×110 的小 canvas，在 zoom pan 事件里同步视口矩形。放在右下角缩放控件上方，可折叠。
成本
约 1 天（自绘）/ 0.5 天（引扩展）。
P1-4

画布内搜索与定位

Ctrl+F

现状：左侧设备库有搜索框，但只能搜「还没加入画布的设备」并定位已有节点；画布上无法直接搜索。真实拓扑 50+ 节点时，找一台设备要靠肉眼扫。

方案
工具条加搜索框（或 Ctrl+F 唤起）：匹配设备名/IP/接口/分组，下拉结果点击后 cy.animate({ center:{eles:target}, zoom:1.2 }) 并高亮 2 秒。顺带把「缩放至选中」补上（Z 键）。
成本
约 1 天。
P1-5

右键菜单 + 快捷键体系

肌肉记忆

现状：右键无菜单（实测：右键后页面无任何菜单元素）。快捷键只有 Ctrl+Z / Ctrl+Y / Escape 三个，且没有任何快捷键帮助入口。

对标：draw.io / Figma 都有完整快捷键表并按 ? 唤起。

右键菜单
节点：重命名 / 关联设备 / 从拓扑移除 / 复制 / 对齐 / 围绕此设备对话；链路：编辑 / 删除 / 反转方向；画布：粘贴 / 全选 / 插入图元 / 自动排布 / 适配视图。
快捷键
V 选择 · M 移动 · C 连线 · Del 删除 · Ctrl+A 全选 · Ctrl+D 复制 · Ctrl+G 成组 · Ctrl+S 立即保存 · 方向键微移（Shift 加速）· F 适配 · Shift+F 缩放至选中 · / 搜索 · ? 快捷键帮助。
注意
现有 keydown 监听已正确排除输入框，扩展时保持这个守卫。
成本
菜单 1 天 + 快捷键 1 天。
P1-6

工具条信息架构重整

13 控件平铺

现状：一条 65px 高的工具条里塞了 4 个模式按钮 + 2 个 details 菜单 + 7 个操作按钮 + 1 个「更多」菜单，靠 @media (max-width:1180px) 换行兜底。功能一多必然溢出。

对标：Figma 的做法是「左侧工具箱（模式）+ 顶部上下文条（随选中变化）+ 右侧属性面板」——操作与对象绑定，而不是全部常驻。

方案
① 模式切换（选择/移动/连线）收成左侧竖直工具岛或保持左侧一组；② 「插入/对齐/撤销/重做」随选中态启用；③ 「新建链路 / 添加设备 / 自动排布 / 拓扑比对」这四个高频主操作保留，其余（编辑信息/删除/导出/查看详情）归入「更多」；④ 把「接口标签」「网格」这类视图开关移到画布右下角的视图控件区，与缩放、鹰眼组成「视图控制簇」——这是 draw.io 和 DNAC 的共同做法，把「编辑」与「看」分开。
成本
约 1.5 天。
P1-7

增量渲染 + 大图性能策略

见 03 / P0-4
方案
① 元素同步改 diff（add/remove/update data/update position）；② 拖拽中只走 Cytoscape 本地渲染，dragfree 才提交并增量更新；③ 节点数 > 阈值（如 150）时自动降级：关闭接口标签、关闭边动画、降低 pixelRatio，并在状态栏提示「大图模式：已隐藏接口标签」。
成本
约 2 天。这是「演示能用」到「生产能用」的分水岭。

P2 · 体验精修（决定「好用」而不是「能用」）

P2-1

拖拽时的智能对齐参考线

现状：只有事后手动对齐（6 个方向，需 ≥2 个选中）。拖拽过程中没有任何提示，用户只能目测。

对标：Figma 的核心体验之一——拖拽时实时出现品红色参考线并吸附。

方案
在 drag 事件中计算与邻近节点的中线/边线对齐，绘制 SVG 参考线并在 ±3px 内吸附；同时给「分布」补两个操作（水平等距 / 垂直等距）。
成本
约 1.5 天。
P2-2

LOD：按缩放层级显示细节

现状：接口标签是全局开关，缩放再小也照常画，节点一多就糊成一团。Cytoscape 已设了 min-zoomed-font-size: 8，但只有字号下限，没有分级显隐。

方案
zoom < 0.5 隐藏接口标签与图元文字；zoom < 0.3 只画图标不画名字；zoom > 1.5 显示更多元信息（IP、型号）。对标 Grafana Node Graph 的分级渲染。
成本
约 0.5 天。
P2-3

批量操作面板

现状：多选后只能对齐。缺失：批量删除、批量移动、批量修改设备类型、批量关联/取消关联、批量归入分组。

方案
选中 >1 个对象时，检视器切换为「多选面板」：显示「已选 N 个（M 设备 / K 图元）」+ 可用批量操作。这是 Figma / draw.io 的标准形态，也顺带解决 P0-3 的反馈缺失。
成本
约 1.5 天。
P2-4

布局算法扩展

现状：只有 ELK layered / direction RIGHT 一种，分连通组件后按 920px 行宽打包（topologyLayout.ts）。

问题：企业网络拓扑是有语义层级的——核心 / 汇聚 / 接入，或 MPLS 的 P / PE / CE。纯分层算法不会知道谁是核心。

方案
提供 4 种预设：水平分层（现有）、垂直分层（核心在上、接入在下，最符合网络工程师直觉）、径向/星型（以选中节点为中心，适合看某台设备的邻居）、网格（适合设备清单式排布）。ELK 换 elk.direction: DOWN 即可拿到垂直分层。
成本
约 1 天。
P2-5

恢复拖拽连线

现状：「连线」模式要依次点两个节点，且没有拖拽反馈（只有边框变色）。React Flow 时代有连接手柄（handle），切 Cytoscape 后失去了拖拽建边的能力——这是交互上的退步。

方案
用 cytoscape-edgehandles 扩展，或在 grab/free 事件里自绘一条跟随鼠标的预览线，落到目标节点上即打开链路编辑弹窗（复用现有 openLinkComposer）。后者约 1 天，可控性更好。
补充
连线弹窗里的接口默认值是写死的 GE0/1 / GE0/0，建议按设备型号推断可选接口，或至少留空提示「待核实」避免假数据。
P2-6

视图书签与 URL 深链

现状：无。切换拓扑时视口重置为 fit，看过的区域要重新找；也无法把「某张图的某个视口」分享出去。

方案
① URL 携带 ?topology=xx&node=yy&x=&y=&z=，刷新与分享可还原；② 用户可保存命名视图（「核心层」「XX 园区」），存在拓扑 metadata 里。大拓扑场景下这两项的实用度极高。
成本
深链 0.5 天 + 书签 1 天。
P2-7

主题适配与代码卫生

主题
节点 background-color:#ffffff、标签 text-background-color:#ffffff 在 Cytoscape style 里写死，dark 主题下是白底黑字块。改为 CSS 变量驱动，在主题切换时调用 cy.style() 重设。
死代码
实测 18 个选择器 0 命中（React Flow 自定义节点 DOM 时代遗留）：.topology-device-node、.device-node-body、.device-node-icon、.device-node-main、.device-node-title-row、.device-node-name、.device-node-meta、.device-node-type、.device-node-footer、.device-node-label-chip、.device-node-group-chip、.node-access-dot、.edge-if-badge、.edge-center-badge、.topology-group-node、.group-node-header、.topology-minimap-custom、.topology-version-badge（TopologyStudio.css 第 80–106 行 + 175 行，约 27 行）。
拆分
TopologyWorkspace.tsx 2,228 行 / 85 个 hook，建议拆出 useTopologyEditor（状态+历史+保存）、DevicePalette、Inspector、CanvasToolbar 四个模块。这不是洁癖——当前文件已经是「改一处要读全篇」的状态。
成本
死代码清理 0.5 天（低风险，可立即做）；主题 1 天；拆分 2–3 天（建议与 P1 改造同批做）。

P3 · 差异化（把领先项放大）

P3-1

LLDP/CDP 邻居发现 → 自动成图

最大差异化

现状：后端 link.source 的 "discovered" 只表示「这条链路两端都关联了资产」，没有真正的邻居发现（全仓 lldp/cdp/neighbor 0 处实现）。所有链路都是人画的。

对标：LibreNMS / NetBox 的自动发现是它们不可替代的原因。手画 200 台设备的拓扑不现实。

方案
扩展健康巡检脚本，解析 display lldp neighbor / show cdp neighbors，产出「发现但未入图」的候选链路列表，在画布上以虚线幽灵线呈现，用户一键采纳。这与现有「证据闭环」设计天然契合——采纳即带上证据引用。
成本
后端 3–5 天 + 前端 2 天。做完这一项，产品从「画图工具」变成「网管系统」。
P3-2

拓扑版本历史与快照对比

现状：有 version 字段做乐观锁，但没有历史记录，改坏了回不去（撤销栈只有 20 步且随会话消失）。

方案
每次保存落一份快照（可只存 diff），提供「历史」面板：时间线 + 差异高亮（新增/移动/删除），支持回滚。与已有的「拓扑比对」能力可以复用同一套 diff 视觉语言。
成本
后端 2 天 + 前端 2 天。
P3-3

把 Agent 协作做成主叙事

现状：Agent 面板能带选中上下文发起对话，能力已经打通，但入口只是右上角一个按钮，且打开后 380px 的侧栏把画布挤窄。

方案
① 节点/链路悬浮时提供「问 Agent」快捷入口，不只是右侧面板；② Agent 产出的结论可以回写到画布（例如「标记这条链路为待核实」「给这台设备打标签」）——让 Agent 从「聊天」变成「操作画布的一种手段」；③ 预设场景卡片（现有 intro 已有雏形）按角色分：故障排查 / 变更影响面 / 合规核查。
成本
约 3 天。这是所有对标产品都没有的能力，值得投。

8.2 实施过程中发现的三个真实问题

1. 扩展路由必须在 manifest 声明。 新增 /discover 后后端直接启动失败：ExtensionValidationError: registered undeclared routes。 平台把扩展可暴露的路由当作安全边界来校验，这比事后审计更可靠 —— 代价是加接口必须同步 extension.json。

2. 采集证据默认读不出来。 巡检产物被分类器标为 sensitive，而 read_artifact_content 默认拒绝敏感内容， 于是邻居发现在线上会永远返回空。这个缺陷只有真跑一遍端到端才会暴露 —— 单元测试里手写的内容 不会被判敏感。已改为显式 allow_sensitive=True；secret 仍然一律拒绝。

3. npm run build 与 npx tsc --noEmit 不是一回事。 此前只跑了后者（不含 tsc -b 的项目引用），14 个类型错误被带进了提交。根因是 import { type MouseEvent } from "react" 遮蔽了 DOM 的 MouseEvent， 原生 window 监听拿不到正确的事件类型。已拆分命名，构建恢复绿灯。

4. 我的第一版版本历史有规模缺陷。 修订记录原本存在一个共享集合里、按 topology_id 过滤，而读取上限是 500 条。 按每图 40 条封顶算，一个工作区约 12 张图之后列表就被截断：部分图纸的历史会静默消失， 而且保留条数是从被截断的列表算出来的，淘汰的会是错的记录。已改为每张图纸一个集合， 并让图纸 id 参与修订查找（A 图的修订 id 不能再用于读 B 图）。 这个缺陷单元测试抓不到 —— 它只在「工作区图纸数量」这个维度上成立。
