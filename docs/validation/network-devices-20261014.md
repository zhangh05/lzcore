# 网络设备业务优化与验证（2026-10-14）

起始源码 `535e5b5ffaf9fefec8657b016c331fd3c5a9cc0b`，在 main 直接维护。范围为网络设备 Skill 的接入、执行证据、配置结果表达、多设备例外处理和历史上下文；设备 Skill 与绘图 Skill 继续独立。

## 已复现问题与修复

- 混合设备的观察与参考只在记录层做交集筛选，仍向仅选 A 的 Skill 返回 B 的 target_id/snapshot。现于共享上下文生产点裁剪目标与快照，先筛选再应用窗口，不提供混合原件作为范围内证据；原持久记录和审计不变。命令经验裁剪连接来源并标记 driver_aggregate，计数／语法反馈不代表某一设备当前状态。
- 基线比较曾只取第一条全局有效参考，其他设备参考可以遮住本设备参考。现按目标身份匹配已确认、当前有效的参考；首次观察仍不自动判定正常。
- 部分巡检重试会重复已成功设备。现接续未成功／未采集设备，保留原命令计划和原证据。原始证据保存失败时明确按 evidence_recollection 重新采集。原任务与后续任务在领域记录中关联；同一来源的重复请求读取同一后续任务，任务创建失败留下可解释的失败记录。
- 设备不可达／部分回显的工具信封可为 ok=True，界面因此容易显示成功。实时卡、历史卡、右侧证据使用同一结果事实区分不可达、部分、未知和采集完成；配置命令处理成功不会表达成业务核验成功。已被后续核对的历史未知结果不再表现为当前未解决的未知。
- 首次 SSH 信任缺少用户可见指纹及确切绑定。保存观察指纹供明确核对，接受请求携带 accepted_fingerprint，握手密钥变化仍拒绝。已信任设备换钥可经显式核对新旧指纹后更新，不能自动接受。

## 用户流程改进

连接阶段诊断统一来自实际错误类别与执行阶段，分别说明地址解析、TCP、主机密钥、认证、终端及命令完整性问题。连接页展示历史验证时间、成功时间及后续处理提示；身份／配置改变失效旧连接观察。设备可以预填创建自身的 Skill，仍需用户明确发布，不隐式授予资源。

管理页按所在视图加载历史与图纸，设备页不请求图纸；历史证据加载失败显示不可用而非伪造空事实。工作区／异步请求变化拒绝过期结果。新增网络业务的巡检记录标签，展示逐设备状态、异常筛选、取消、未完成设备重试和完整证据读取。巡检作业仍隐藏于通用任务中心，其事实继续归网络领域。

领域提供 presentation 执行索引，经原 ToolRuntime.execute_node → ToolRuntimeClient.invoke 治理后发布到实时事件。UI 索引不流式复制任意二进制或完整原件；完整命令回显仍从运行结果读取，巡检完整原件经已有认证 Artifact API 读取。没有增加模型可任意指定主机／凭据的入口，没有增加固定业务步骤或配置关键词许可门。
