## 共享合同及已复现问题

| 缺陷或能力缺口 | 修复与边界 |
| --- | --- |
| 动作必填只在模型规划入口生效 | SemanticValidator 与 ToolExecutor 消费同一个条件必填解析器，覆盖核心及扩展元数据；无效参数在 handler 前拒绝。False/0 是有效值，空替换是删除，空浏览器输入是清空。 |
| 无返回值/缺少明确 ok 被包装为成功 | 执行器复用 ToolRuntime 的既有 outcome 解析，不另建状态；NULL_RESULT/TOOL_RESULT_INVALID 不伪造成功，提示核对效果，禁止自动重试。 |
| 模型 schema 根约束丢失、任意类型被强加 string | 深复制完整 schema，包括根与嵌套约束；profile_set value 保留原始任意 JSON 类型。静态 OpenAI 投影与生产目录使用同一 ToolSpec/Adapter。 |
| 旧 namespace 提示掩盖实际功能，目录另有描述副本 | 功能说明来自 canonical registry，namespace 只补选择与证据指导；去掉重复约束和强制实施方式。FileStore 已有新功能重新对模型完整可见。 |
| 缺失 old_string 插入内容、重复文本选错位置 | 执行前拒绝缺参；编辑要求唯一上下文或显式 replace_all，未命中时给出原文件和传入字符串的换行类型；不会猜位置或替换字符。 |
| 读取和编辑的 CRLF 合同不一致 | 读取/精确编辑保留原始 UTF-8 换行，read 返回换行约定及末尾换行状态；字节数与字符数分开，读取摘要不再误称写入。非 UTF-8 返回明确失败，其他编码走文档处理。尾部分页也明确标记非完整读取。 |
| patch 不支持零范围插入、错误计数可能放行、dry_run 被忽略 | 单文件 unified diff 全部 hunk、位置、计数、上下文和无末尾换行标记先验证，最后一次原子写；支持零范围插入/正文含 @@/CRLF，dry_run 仅预览，后续 hunk 错误不会部分修改。 |
| 无源码内容定位工具 | workspace.file search 返回路径、1 起始行/列和片段、分页、扫描与跳过证据。范围为 files/data、files/tmp、inbox；二进制/非 UTF-8/符号链接/大于 4 MiB 明确跳过，文档附件仍由 FileStore 搜索。 |
| 大 CSV 静默截掉超过 10,000 行、坏 JSON 当 CSV、错位列被裁/补 | 所有格式使用同一输入边界，超限/格式错误明确失败；稀疏 JSON 用全部行的首见列集合，后续行的新列不再被漏掉。 |
| parse 预览无法可靠组合成全量计算 | data.manage 新增 source_filepath/right_source_filepath，按工作区路径读取原始 UTF-8 文件，返回 SHA256 来源；文件源与 rows/text 混填会失败。模型仍可自主选择执行器和其他已授权方法。 |
| null/布尔值/非有限数污染统计、小样本中位数不正确 | 排除数量明确，null 正确计数，分位数使用线性插值，标准差标明总体口径；稀疏列支持统计、筛选、排序等完整动作。 |
| 多对多 join 和稀疏 pivot 产生巨大返回/内存 | 全输入处理和完整计数保留；join 只保存前 200 行，pivot 展示最多 200 行/200 列（默认 50 行），明确总维度、返回维度和截断。aggregate/distinct 也标注结果预览，后续全量计算继续从原始数据出发。 |
| extract_entities 实际只有词频 | 保留关键词并增加确定性 IPv4/IPv6、邮箱、HTTP(S) URL 候选和可核对字符跨度，最多显示 100 个、总数/截断明确；不冒充语义人物识别。 |
| 正则复杂回溯拖住执行线程 | regex 计算有一秒可中止时间上限，超时报告未完成和禁止自动重试；完整计数与最多 100 个展示结果分开，无关键词/语法过滤。 |
| diff 无声截断输入、行和长文本 | 完整标准 unified diff，返回实际增删行计数及无末尾换行标记，不用裁过的片段冒充完整比较。 |

regex 已由 dateparser 间接引入桌面锁文件，本轮声明直接依赖；锁定版本不变，没有全依赖升级。默认权限、写入审批与未知写入回查合同保留。

## 描述大小与实际选择

18 个核心 namespace 的补充指导/禁用说明由 9,030 字符降至 1,765 字符，约减少 80%。这是补充指导，不等于全部工具 schema。完整目录保守估算从约 25,882 token 到约 26,200 token：新增能力、完整约束、结果覆盖及路径/换行说明保留后，整体请求成本基本相当，不宣称 token 大幅减少。

工具不是越短越好。保留正确动作、必填参数、权限/副作用、可绑定结果、单位与覆盖范围；不以重复话术代替实际权限，不前置过滤模型工具。改动参考 [Anthropic 工具工程说明](https://www.anthropic.com/engineering/writing-tools-for-agents) 与 [原生工具协议文档](https://platform.claude.com/docs/en/agents-and-tools/tool-use/how-tool-use-works)。正则时间边界使用 [regex 维护者提供的 timeout 能力](https://pypi.org/project/regex/)。

### 本次新增确认及修复

1. **工作区相对路径被持久化误脱敏**：`files/tmp/核对结果.json` 被存储脱敏从中间 `/tmp/` 截成 `files[REDACTED_PATH]`。在共享 storage redaction 匹配中限定真正绝对路径的起点，保留相对路径和 URL；本机 Unix/Windows 路径、凭据及容器路径授权规则仍受既有测试保护。最终真实模型回复中的输出路径完整保留。
2. **知识导入结果无法组合**：工具旧 helper 读取不存在的 `result.source.source_id`，实际领域服务返回顶层 source_id，导入已经成功却给模型空身份。工具/API 共用 knowledge service 的 artifact 导入；API 保持既有传输结构，工具从实际顶层身份继续 read。删除两份重复导入实现，不增加持久状态或兼容事实投影。
3. **知识写入未知证据丢失**：旧 helper 把领域服务的未知写入字典改成普通错误，丢失 error_code/executed/禁止自动重试。现在完整保留领域结果；故障注入验证 EXECUTION_UNKNOWN 与仅一次写入尝试，不重放。必要回归先在旧代码复现空 source_id，再验证修复后的工具与 API 可读身份及未知写入字段。
4. **精确编辑失败诊断补充**：模型双重转义换行或 unified diff 漏无末尾换行标记时明确说明原因；仍拒绝不匹配输入，不自动解释反斜杠、不猜源字符、不补写换行。
