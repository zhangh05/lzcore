# QueryLoop：目标、证据与恢复

入口：`core/runtime_engine/query_loop.py`；目标：`goal_loop.py`；模型与执行类型：`models.py`。内核维护通用任务控制，厂商命令和图纸规则由扩展提供。

## 一轮工作

1. 装配生产系统提示、原生工具定义、历史、受治理上下文、可信运行指导和当前请求。
2. 模型提出原生调用或答复；运行时校验工具身份、完整参数和计划依赖。
3. 模型节点经 ToolRuntime.execute_node 执行；外部/审批调用经 ToolRuntimeClient.invoke。
4. 保存工具结果与证据，推进 tracking、goal_loop 和 runtime_recoveries。
5. 核对完成缺口：充分则收尾；有可行工作则继续；不能完成则保存具体缺口和原因。

工具失败是观察，不等于整个任务失败。失败项不抹掉独立成功项；最终结果必须反映用户要求的覆盖范围。

## 观测新鲜度

可安全重试不等于可复用旧结果。成功只读调用默认再次观察；只有 action 合同明确声明 `observation_cache: turn` 的纯数据计算，才允许一轮内复用同参数结果。目前是 `data.manage`、`text.analyze` 的纯只读计算，文件、浏览器、拓扑、作业和外部状态读取均不复用旧观察。

执行清单记录状态修订号；成功副作用推进修订。已明确失败且不可能继续执行的同参数调用，仅在状态未变化时抑制重复。状态变化后可重新评估，但未知外部写入仍由操作账本保持 read-back/reconcile，不能因此自动重放。

Provider 错误投影保留稳定错误码；`provider_recovery_events.diagnostic` 保存有长度上限、已脱敏的具体原因、可用 HTTP 状态和错误类型。拒绝请求不会原样无限重试。可信运行身份还注入服务器 OS 与原生 shell，不能靠模型猜测宿主平台。

## 错误与下一步

| 证据 | 下一步 | 禁止 |
| --- | --- | --- |
| 参数/schema/标识错误 | 读取合同，改参数或重新解析对象 | 原样重复无效调用 |
| 只读观测失败 | 保留目标，寻找同目标的可用证据 | 用文档代替当前状态 |
| 领域明确要求的证据缺口 | 用 plan_goal_ids 关联替代调用并接受运行时核验 | 仅凭模型声明关闭目标 |
| 写入明确未发送 | 修正已授权调用，执行尚未发送部分 | 宣称已执行 |
| 写入未知或仍在执行 | read-back/reconcile，保持不确定性 | 自动重放未知写入 |
| queued/running tracking | 用原 task_id 轮询同一生产者 | 新建同任务当作轮询 |
| 权限拒绝或依赖不可用 | 说明边界，改为可行路径或具体受阻结果 | 绕过治理网关 |
| 审批等待 | 保存 checkpoint，等待同一决策集终态 | 创建“继续”用户消息或提前连接写入 |

`plan_goal_ids` 是关联，不是证明。通用只读目标与领域严格恢复的核验条件不同，以对应 goal 的证据种类、资源和事实要求为准。成功替代路径可以完成目标，失败尝试仍在记录里。

## 长任务、容量与无进展

普通回合持续有进展时没有固定总轮数或累计墙钟终止上限。单次连接/工具/Provider 超时仍返回事实；调用方预算、子 Agent profile、Provider 容量和显式取消仍有效。`max_query_loop_iterations=0` 允许供应商故障恢复；正值控制供应商失败兼容回退，不截断持续产生进展的工具工作。

完全相同的连续工具失败、重复无变化修改和永久 Provider 拒绝可以触发收尾。拓扑连续三次明确 changed=false 会阻止无效提交，但不缩减合法节点数量或正在推进的编辑。取消保留证据，明确记录取消。

历史和普通工具正文不静默截断。超过可用模型窗口返回 context_capacity_exceeded；不能反复提交同一超大请求。输出截断保留公开前缀与协议状态：未完成调用不执行，模型需重发完整原生调用，必要时拆为依赖有效的批次。正文续写不等于执行半段 JSON。Anthropic 原生历史中不合法的 tool input 在出站时保存为明确的无效参数对象，保留拒绝事实和原调用 ID；不能让反馈请求因历史参数不是 object 再次被拒绝，也不能将其变成可执行的空参数。Thinking/signature 等合法原生块原样保留。model_completed 的 finish_reason/output_truncated 区分容量与工具失败。

## 计划和委派

依赖调用使用 plan_step_id、plan_depends_on 和 plan_bindings，绑定仅能来自声明的安全结构化字段。独立只读可以并发；有依赖或副作用的步骤按序推进。

agent.manage 用于值得分工的独立目标。工具面经 profile、父 Skill 和服务端范围重新核定；不能声称所有子 Agent 都不受预算约束。父任务核对范围、证据和缺口，不能把子 Agent 文字当作更高授权或确认事实。

## 完成与恢复

任务 execution_outcome 与单次 tool_execution_outcome 分开。记录的 succeeded/failed/cancelled 等生命周期也不能直接等同于设备写入结果。终态答复应覆盖用户要求、实际证据、失败/缺失范围和未知写入。

进程中断后的收尾对齐 job、会话消息和回合日志，幂等补齐中断结果，不重新执行工具。断线续流只读 turn_logs；页面离开不取消任务。控制与保留期见 [API](API.md)。

验证应覆盖合法输入、无效调用、部分成功、依赖绑定、追踪、未知写入、审批恢复、中断及幂等收尾。不能仅验证最终措辞就宣称循环可靠。
