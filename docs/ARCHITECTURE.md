# 联智中枢（LZCore）系统架构与运行时白皮书

> **Enterprise Runtime Architecture & Governance Whitepaper**
> 本规范系统性阐释 LZCore 的底层设计原则、因果状态机模型、多协议模型推理适配、工具治理网关与租户数据防线。

---

## 1. 架构总览与分层边界

联智中枢的核心架构边界由物理执行流而非视图页面或提示词模板决定。各层级之间权责明确，呈单向防御纵深：

```text
 ┌────────────────────────────────────────────────────────────────────────┐
 │ 1. 接入与协议适配层 (Access & Transport)                               │
 │    · RESTful API 路由 (`backend/api/`) 与 WebSocket 双工网关            │
 │    · 身份认证鉴权、OIDC 统一身份与请求速率限制                         │
 └───────────────────────────────────┬────────────────────────────────────┘
                                     │ /api/agent/message & WebSocket 流
                                     ▼
 ┌────────────────────────────────────────────────────────────────────────┐
 │ 2. 会话编排与上下文管理层 (Agent Session & Context)                    │
 │    · `agent/app/` 会话聚合与 `agent/runtime/` 实例化                   │
 │    · 跨轮次历史合并、动态证据索引与长效记忆（Memory）召回              │
 └───────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
 ┌────────────────────────────────────────────────────────────────────────┐
 │ 3. 认知中枢与单一事实源引擎 (SSOT Cognitive Core)                     │
 │    · `SSOTRuntimeEngine` 维护权威生命周期状态机 `TaskState`            │
 │    · `QueryLoop` 驱动模型多轮迭代规划、推理与断言门禁                  │
 │    · 目标驱动自愈系统 (`goal_loop`、`plan_goal_ids`、`runtime_recoveries`)│
 └───────────────────────────────────┬────────────────────────────────────┘
                                     │ 结构化调用意向
                                     ▼
 ┌────────────────────────────────────────────────────────────────────────┐
 │ 4. 治理网关与执行沙箱 (Tool Governance & Execution Sandbox)           │
 │    · `ToolRuntimeClient` 统摄全量能力 (Manifest Registry)              │
 │    · 细粒度权限校验、设备凭据绑定与命令语义分类 (command_semantics)    │
 │    · 敏感数据自动脱敏引擎 (Redaction) 与不可篡改的操作审计账本         │
```

## 2. 单一事实源引擎（SSOTRuntimeEngine）与状态流转

### 2.1 任务权威状态与对外投影
- **单一事实源（`TaskState`）**：在整个系统生命周期中，一次运维任务的真实状态唯一确权于服务端的 `TaskState`。前端交互层、历史日志或任何第三方轮询客户端均无权篡改该状态。
- **标准化结果投影（`AgentResult`）**：对外输出（无论是 HTTP 响应、SSE 推送还是 WebSocket 广播）统一派生自 `AgentResult`。系统杜绝在中间代理或客户端维护第二套状态缓存，杜绝状态脱节。

### 2.2 无墙钟截断与因果连续性
- **拒绝人为时间截断**：平台摒弃了简单粗暴的“固定运行 N 秒即超时”的传统设计。QueryLoop、耗时巡检任务与长作业跟踪均由实际任务目标是否达成、是否取得完整闭环证据以及运维人员的显式取消信号驱动。单次网络探针或外部 HTTP 调用的协议级超时仅作为底层客观事实反馈给模型，而非导致整体任务瘫痪。
- **不可篡改的单向因果流**：在推理迭代过程中，新产生的认知决策、观察事实与恢复目标仅以新事件形式单向追加至消息流尾部，绝不向前修改或覆盖历史会话，从而严格保护因果一致性，并充分复用底层大模型 Provider 的 Prompt 缓存加速。

## 3. 多模型协议状态管理与推理保留

系统原生支持多家业界前沿的基础大模型，并在进程内提供高保真的原生协议状态保留机制：

### 3.1 协议保留矩阵
- **Anthropic Messages 协议**：原生保留完整的 Content Blocks 序列（包含 `thinking` 深度思考链、`signature` 签名与 `redacted_thinking` 混淆思考块），流式传输时实现思考流、参数调用与文本输出的无损合流。
- **OpenAI 兼容协议**：原生保留 `content`、`reasoning_content` 以及增强型的 `reasoning_details` 字段。
- **MiniMax 协议**：针对特有的累积快照流机制（Cumulative Snapshot Stream）提供专用状态重组管道。

### 3.2 跨轮次持久化与安全脱敏边界
- 进程内的复杂原生协议状态专用于当次 QueryLoop 的无损多轮推理。
- 面向最终用户的公开会话历史中，包含已保存的阶段性分析（`stage_outputs`）与全部受治理工具的执行摘要，不人为施加过度短视的截断限制。
- 所有公开文本在落盘与网络传输前，必须强制经过隐藏推理块剥离器与敏感信息动态脱敏网关，确保运维机密永不泄露。

## 4. 工具治理网关与沙箱隔离

平台中所有工具的调用必须由 `ToolRuntimeClient` 统一介入执行：

```text
Tool ID ──> Manifest 解析 ──> 租户隔离校验 ──> Skill 范围授权 ──> 沙箱执行 ──> 动态脱敏 ──> 审计记录
```

1. **Manifest 清单自愈与校验**：
   - 依赖 `core/tools/manifest_registry.py` 作为全平台能力的单一真实注册表。
   - 所有工具必须具备声明式 JSON Schema 契约，模型仅能通过标准 Function Calling 接口调用，禁止在 Prompt 文本中注入非受控的伪工具。
2. **工作区物理越界防护**：
   - `workspace.file` 核心文件工具支持大文件完整读取与流式分段读取（支持 `offset` 与 `limit` 显式分页控制）。
   - 内部集成物理路径沙箱，严格阻断任何包含 `..` 相对路径跳转或越过当前 `workspace_id` 根目录的访问请求。
3. **命令语义分类与设备执行隔离**：
   - 网络运维操作拒绝依赖模型自行上报的 `action` 字段，服务端基于真实的命令语法分析引擎（`command_semantics`）对输入指令进行强制分类（区分只读指令与配置下发指令）。
   - 设备的真实账号权限是底层执行的最终防线。

## 5. 目标驱动自愈与状态恢复机制

### 5.1 恢复目标（Recovery Goals）闭环
- 当只读观测因网络抖动或临时异常失败时，系统将该事件捕获为带有语义的恢复目标。
- 模型在下一轮迭代中可通过 `plan_goal_ids` 挂载替代方案。只有在替代方案返回真实、有效且成功的物理只读证据后，系统才允许注销该恢复目标。
- **多目标严格隔离**：针对多设备并行巡检场景，单台设备的掉线或异常严格限定在其专属的资源上下文内，绝不污染或阻断其他正常设备的任务推进。

### 5.2 确定性停滞检测（Stall Detection）
- 虽不设人为时间上限，但系统严密监控逻辑死循环：当检测到模型反复提出完全一致的无效工具调用、或者底层 Provider 抛出不可逆的认证/配额绝拒时，系统触发防死锁机制，将任务安全收敛为结构化 `blocked`（受阻）终态，清晰呈现当前瓶颈证据，等待人工干预。

## 6. 零旁路变更审批扩展（Approval Extension）

针对企业核心基础设施的配置变更安全，系统支持可插拔的人工审批拦截体系：
- **操作冻结与 Checkpoint 封存**：当关联 Skill 开启审批要求时，核心拦截器在真实配置命令触碰物理网络前一刻截获该调用，将调用参数、版本指纹与完整的 QueryLoop 上下文冻结入库。
- **异步安全恢复**：审批人员通过前端工作台核准后，服务端重新核验环境有效性，原样恢复 Checkpoint 继续驱动核心认知循环，在原逻辑节点推进后续验证，无需用户在前端手动发送“继续”指令。

## 7. 多租户数据安全与前端职责

- **多租户隔离规范**：全链路数据读写（文件系统、向量库、运行日志与作业队列）必须经过已验证的 `workspace_id` 进行边界圈定。
- **凭证机密存储**：平台机密信息采用 `Fernet` 算法进行高强度信封加密，主密钥由环境注入，彻底杜绝明文风险。
- **前端工作台契约**：前端依托 **Zustand** 构建响应式数据中心与交互白板，通过 **WebSocket** 接收后端实时事件流，坚决履行展示与人机交互职责，严禁在客户端越权模拟或判定服务端的安全决策。
