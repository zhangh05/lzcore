# Coding 状态与工具合同优化核验：2026-10-07

本轮实施三个源码核验后的优化点，延续既有 Candidate / Review / Task 和 ToolRuntime 合同。模型自行选择计划、工具、修订与表达；未恢复真实模型压测。

## 已实现

| 问题 | 实现与边界 |
| --- | --- |
| EXECUTION_UNKNOWN 无显式恢复入口 | `agent.manage(reconcile)` 在可信父任务/会话内回查停止的 worker、原 daemon 的容器/代理/网络、一次性验证资源与准确源码。保存 `execution_recovery` 与 CAS 事件，进入 review_incomplete；旧检查和终态 Review 不改写。新 QA 必须在新批次实际执行完整检查，才能接受和整合。旧恢复不能覆盖后来产生的 unknown。 |
| Task 兼容字段仍参与 QA 事实 | QA 绑定、检查缓存、裁决、完整/无效报告及收尾统一从 Review Store 读取/保存；已封存实现的源码、检查合同和发布从 Candidate Store 读取。删除 Task 的候选、QA、验证、资源、基线、变更、发布及修订观察镜像与投影函数；Task 只保留 v2 执行参数和 worker 生命周期。实时实现检查/资源在 building Candidate 中保存，QA 全程在 Review 保存。旧 Task 在启动恢复前一次性迁移，持久化删除旧字段；Store 缺失不能用新 Task 重建。评审创建中断通过 Store 创建意图和清理证据恢复缺失记录，缺失检查不能补成通过。 |
| 重复 Tool Schema 说明占用上下文 | 五个公共 plan_* 字段保留在每个工具中，类型、枚举、默认值、参数约束和发现能力完整保留。完整编排语义在共享 Runtime prompt 注入一次，字段说明精简。未加入按关键词/任务类型/token 预算过滤工具的逻辑，未截断工具说明或证据。 |

未封存 building Candidate 在 worker 已停止、原资源回查闭合后，才按实际源码封存为 execution_unknown，再保存恢复证据进入 review_incomplete。活动 worker 不可通过回查封存；检查不补成通过。缺失 Review 的创建意图与清理回查保存在 Store，清理确认丢失也能保留准确资源与中断评审。

回查只观察，不启动/停止环境或执行应用命令。无法确认原 daemon、资源仍存在、worker 活动、源码变化或旧记录缺少可信资源身份时保留 unknown。已封存的确认清理可以作为资源闭合证据。生产者的未知检查不能变成 PASS，接受来自新 QA 的实际完整检查。源码修订仅复制回查后已知的源码，不继承通过状态。

独立团队验收器分别核对恢复证据、原资源身份、一次性验证容器、新 QA 的准确检查与实际发布树；历史 unknown 完整保留，未降低检查命令或业务需求。真实 Docker 核验脚本新增活动容器拒绝恢复、丢失清理确认后只读 info/inspect 证明资源不存在两项探针，随对应提交的 CI 执行。

## 本机证据

- 全后端：2307 通过、11 跳过；真实 Docker / 分布式集成属于显式启用的 CI 环境，不能将本机跳过记为通过。
- 新恢复回归：16 项，覆盖实现/QA unknown、禁止重放、旧证据不变、新 QA 整合、再次 unknown、活动 worker、作用域、源码变化、daemon 变化/不可达、一次性验证资源、Store 缺失和伪造 Task 检查缓存。
- 删除旧结构回归：实时和终态 Task 无镜像、迁移后持久化删除字段、既有 Store 优先、未知证据不重放、缺失新 Store 不重建，连同既有创建中断恢复及修订闭环覆盖。
- 前端：408 项通过；生产构建、类型/CSS 检查、设计 token 检查、文档一致性与静态错误检查通过。
- 完整目录核对：25 个工具保持可见，所有 action、参数、嵌套约束、绑定及输出说明保留；Schema 前后剔除 description 后结构相同。
