# Coding Runtime

长任务使用持久化任务历史、可接续模型窗口和受系统隔离的工程环境。角色共享完整工具目录；权限仍由 ToolRuntime、认证主体、工作区与当前发布 Skill 核定。

## 模型窗口与证据

`ContextContinuation` 在完整工具交互边界建立不可变归档。归档保存脱敏的完整消息、原生协议块、任务/目标状态、未知写入清单及父归档引用，按主体/工作区/会话隔离并校验 SHA256。发布失败保留旧窗口，不能丢弃证据后继续。新窗口保持原始治理约束，携带最近完整工具交互及归档引用，历史细节经 `system.manage(context_index/context_read)` 回查。

输出预留、安全余量、系统提示词和完整工具定义共同计入实际模型容量。配置的输入窗口是优先接续边界；超大原始要求仍可使用实际模型容量。仅原始治理约束本身无法容纳时返回 `context_capacity_exceeded`。审批暂停另保存窗口生命周期，恢复不把审批接续提示当作新的原始要求。窗口切换不执行工具，不重放完成或结果未知的写入。

原始模型提案与实际工具交互使用不同合同：原生协议完整保存在归档，`tool_calls` 的显式列表决定发送给模型的交互；空列表表示未执行的提案。统一协议投影处理编号去重、批量编译和重复调用抑制，保留原生思考块/签名，禁止留下没有对应结果的调用。SSOT 适配与持久化恢复都保留 `None` 与空列表的区别。厂商拒绝请求时另记录仅含摘要哈希、字节数、块计数和协议违规计数的诊断，不记录提示词、思考内容或凭据，不盲目重试相同 400 请求。

## 执行环境

`DockerProjectEnvironment` 是服务端配置的执行适配器。严格工程任务只挂载生成工程，容器非 root、根目录只读、权限/进程/内存受限。它没有框架、Evaluator、宿主 HOME、凭据或 Docker Socket。项目使用内部网络，独立 broker 只允许指定依赖 registry 的 TLS 出站；预览只发布服务端指定的 loopback 端口。

Shell 与 Python 都经原有 ToolRuntime 进入同一适配器。系统隔离不可用即失败，不回退宿主 Shell；普通受信任本地执行保持原有独立合同。超时/取消清理整个任务容器及后代进程，清理未确认记录 unknown，禁止自动重试。关闭后的工作区绑定保持关闭，迟到调用不会回退宿主。跨主机 daemon 只能映射服务端明确指定的 scratch 根。

严格工程执行的 Shell/Python 默认目录统一为可写工程根目录，容器描述与结果的 `container_cwd`/`working_dir` 给出实际位置；显式 `working_dir` 仍是工作区相对路径并限定在挂载工程内。普通本地执行默认工作区根目录，`workspace.file` 始终使用工作区相对路径，不因 Shell 目录改变。

脱敏区分宿主诊断路径与容器操作引用。正在运行的服务端 DockerProjectEnvironment 绑定允许 exec.run 输出、对应模型工具消息和原生参数归档保留容器 tmpfs 的 /tmp 路径；context_read 可取回同一引用。用户/系统消息、宿主路径、越界路径和凭据仍脱敏。权限不从模型参数或工具自报 isolation_level 推导，已关闭绑定不能获得该路径例外；此例外不赋予额外执行权限，也不允许把临时目录工程当作已整合源码。

## Coding Team

`coding_agent`、`frontend_agent`、`qa_agent` 与研究/文件/数据角色共享工具目录。`coding_assignment` 声明工程、文件或目录责任、已存在的前置任务和验证命令；`.` 表示整个工程，不支持隐含 glob。服务端父任务/会话身份决定归属，模型不能覆盖它们。当前领域 Skill 不能被静默迁移到工程副本，因此这类委派要求无领域绑定的编码任务。

实现者使用独立工作区的工程副本；实现依赖消费 `integrated` 的发布结果，QA 的 review_subtask_id（包括显式 depends_on 中同一目标）消费 changes_ready/validated 的成功候选，避免“QA 等整合、整合等 QA”的循环。QA 任务不能作为发布依赖。任务完成或整合后调度已授权、同父任务和会话的等待任务；进程恢复仍通过 agent.manage(start) 启动原任务，不重复创建。依赖失败/取消会形成明确 dependency_failed 终态。QA 使用准确候选源码的独立副本，不继承实现者对话；实现者的完成声明不能代替验证。每个验证命令表示一个可执行程序和字面参数，运行结果、退出码和 QA 前后源码摘要共同决定验证状态。任意命令退出 0 仍不等于完整业务验收，独立 Evaluator 单列事实。

实现者提出最终回复时，服务端完成观察通过受治理执行入口运行 assignment 声明的检查，并绑定当前完整源码摘要。已确认失败回到同一实现者 QueryLoop，保留原合同和工程继续纠错；未知执行结果终止自动续跑并保留证据。检查通过且停止后代进程后源码仍一致，才能进入 changes_ready。该观察由 SubagentRuntimeControl 注入，调用者 metadata 不能伪造回调；它是候选就绪证据，仍须独立 QA 和真实整合。agent.manage(get) 同时回传源码文件数、字节数、已记录模型调用与完成检查状态等观察，不将它们解释为业务完成百分比。编码角色缺失 coding_assignment 时，规划校验和工具治理均返回缺失字段，不能猜测工程位置。

整合前检查 QA 身份、候选摘要、责任范围和父工程当前基线。与受治理文件/执行操作共享工作区锁，并冻结项目容器的后代进程。事务先保存前后内容与 journal，再逐文件发布；中断后回查哈希，确认整合、回滚已知部分或保留 unknown。用户/其他分支已改同一文件时返回 conflict，不覆盖。这里是独立文件树副本及变更集整合，不是 Git 分支管理，也不保证任意外部编辑器绕过文件锁时的整棵目录瞬时原子性。

发布 journal 在工作区锁内保留持久化递增顺序；失败保留间隙，恢复与重复读取不分配新的已整合身份。团队验收核对每个候选的独立 QA 与真实 journal，从最初完整源码基线按发布顺序验证 before/after 链，对比最终父工程的完整源码树（包含未改动文件和路径缺失）。允许经过新一轮 QA 的连续修改，不允许未评审改写、断裂的变更链或伪造顺序。

强隔离工程进入 Coding Team 后，源码写权限属于实现分支；父任务转为协调者，QA 使用只读源码挂载。文件工具同步检查环境所有权，受治理整合仍可在锁内发布。转换只在没有正在执行的命令时进行，先暂停后代、退出写容器，再创建只读容器；失败关闭环境，不恢复写权限或回退宿主。QA/协调者允许写声明的生成目录、node_modules/.venv/.pytest_cache 与 /tmp，不能为清理删除源文件。只读角色的生成输出必须使用目录；文件型生成物可在实现分支生成，但不能作为只读角色的独立可写挂载。外部编辑器和未绑定强隔离环境的 trusted local Shell 不受这层内核挂载控制，最终完整源码树门禁仍拒绝未评审改动。

预览监听使用容器的 HOST=0.0.0.0、PORT=8080；浏览器 origin 使用各工作区独立的宿主转发端口。实现、QA 和协调者使用相同监听合同，源码读进程环境，不为切换分支改监听端口。平台只发布选定的宿主 127.0.0.1 入口。

## 模块职责

| 原入口 | 保留职责 | 独立模块 |
| --- | --- | --- |
| `query_loop.py` | 单回合状态机与兼容出口 | 模型窗口、工具准备、执行器、恢复、跟踪、审批接续、终态投影、消息序列化、工具目录 |
| `ssot_runtime.py` | 会话接入与回合生命周期 | 上下文、Provider、持久化、投影、记忆、工具身份适配 |
| `network_operations/service.py` | 工作台资源选择与协调 | 设备/连接、脚本、巡检计划/执行/生命周期、发现、基线/观测 |
| `TopologyWorkspace.tsx` | 工作台组合与视图状态 | 文档状态、保存/冲突/历史、协作、设备/区域/选区命令、版本、导航、Inspector、独立面板/对话框 |
| `NetOpsCanvas.tsx` | 单一渲染实例组合与控件 | 加载、样式、命中测试、拖拽/吸附、选择、图形投影、主题、导出 API、导航/小地图、覆盖层 |

每个入口保留现行调用合同。没有复制执行状态机，没有运行时源码拼装或 `exec` 拆文件。区域身份仍为 `canvas_items.item_id`，节点 `region_id` 引用它；主题只改变呈现，不改图纸颜色与坐标。

## 验证边界

310 轮 QueryLoop 测试使用确定性 Provider 与真实治理执行路径，验证窗口接续、完整证据和未知写入约束，不是 310 次真实 LLM 交付。真实内核隔离、真实 Provider 工程交付、独立 Evaluator 和浏览器回归分别留证。见 [编码压测](../CODING_BENCHMARKS.md)。发布和部署以用户明确授权及对应验收证据为前提；检查结束不自动授权 tag、Release 或部署。

工程源码分类由 `coding_assignment.generated_paths` 显式声明可再生输出路径（例如 `["dist"]`），默认空。`build/`、`dist/` 或嵌套同名目录本身不构成生成物身份；构建脚本属于源码。快照、QA、候选摘要、事务整合和团队验收使用同一份合同，QA 从实现任务继承且不能另行削弱。项目根、路径越界及项目配置文件不能被声明为排除输出。

子任务总生命周期与工具请求等待分开：`background=false` 最多等待 15 秒，仍在执行就返回同一任务句柄；不会因外层请求超时取消有效工作。`get/status` 查看持久化状态，`start` 仅启动前置依赖已满足的 created 任务。启动通过主体/工作区范围内的文件锁跨进程领取任务，并在锁内重读状态；首次持久化终态不可被旧工作覆盖。取消同时通过实时信号和主体/工作区范围内的持久化状态传播，跨进程可见。压测结束取消、等待并核验其全部委派分支清理，清理未知不能计为通过。

自动轮询停止属于观察者状态，不能改写生产者的 status/done/terminal。重复 running、观察失败、缺失跟踪字段或轮询异常只记录 auto_polling=stopped 与 stop_reason，并退出本次自动观察；子任务仍保持最近确认的生命周期。下一次显式 get/status 回查同一任务，不创建副本或接管源码。生产者给出的真实失败、完成与取消终态仍保留；revision/observation_token 用于识别状态名称不变时的新进度。

窗口续接从既有 tracking_events 投影每个工具/任务的最后观察，保存原句柄、状态、来源调用及准确回查参数，不复制轮询历史或原始工具数据。它是已观察事实而非实时状态或交付证据；模型继续回查同一任务，不因窗口更换重新委派。该投影不建立第二套任务调度器，不执行工具，不重放写入，也不绕过候选 QA 和整合合同。

### 不可变源码的构建验证

只读工程内的挂载输出目录不能支持标准构建删除整个目录。服务端将 assignment 的精确 argv 验证命令绑定到执行环境；协调者/QA 执行这些命令时使用独立、一次性的工程快照容器。复制源码摘要、已声明的输出和受范围约束的依赖缓存，构建副本允许删除/重建输出根。停止全部后代、确认清理且副本与原候选源码摘要都未改变后，只回传声明的生成目录内容，保留原挂载根。验证证据包含摘要、执行器和清理状态。任意额外命令仍使用只读源码挂载，不能将模型参数变成源码写权限；输出符号链接、源码变化或未知清理均拒绝。
