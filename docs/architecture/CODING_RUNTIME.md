# Coding Runtime 架构改造

本轮目标是长周期任务的可接续执行、受系统约束的工程执行环境、独立业务验收和可验证的多 Agent 变更整合。保留模型的完整工具能力；任何角色、摘要或提示词都不构成权限控制。

## 状态与证据

上下文窗口与任务历史分开管理。窗口接续前持久化可校验的原始记录，明确新窗口引用哪些归档。真实用户约束保持原文，当前目标与未知执行结果由持久化状态提供；归档内容通过治理工具按记录、范围回查。只在完整工具交互边界建立窗口，不能遗留孤立 tool result，也不能自动重放未知写入。

## 执行环境

本地普通执行与严格工程执行使用明确的环境适配接口。严格环境只能访问获授权工程和必要运行依赖，不能访问框架源码、验收器和宿主凭据。系统隔离不可用时明确拒绝，不能回退宿主 Shell。验证必须包含实际越界读写、子进程、符号链接和取消后的进程清理。

## 团队与变更

工程角色使用同一 Runtime 与工具治理。任务依赖、修改责任、基线摘要、变更集、验收证据和合并状态分别记录；任务成功不等于变更已整合。整合检查基线与冲突，QA 结果不由实现者自报替代。

## 模块边界

运行核心按执行、模型传输、证据投影、失败恢复与跟踪分层；接入层管理会话生命周期和持久化。拓扑按文档、交互、绘制和面板分层；网络扩展按设备连接、巡检、发现及观测分层。保持现行唯一图元/区域身份，保持外部接口和行为回归。

## 验收状态

上下文窗口接续、不可变归档、当前会话的治理回查和运行记录已实现。310 轮窗口生命周期检查验证有界窗口与完整证据回查；这是一项程序化检查，不是 310 次真实模型工程交付。隔离执行、团队变更和模块拆分仍在本轮改造中，尚不能作为实现或压测通过的声明。最终版本和 Release 只在各阶段检查及多轮压测结束后更新。
