# Coding Runtime

长任务使用持久化任务历史、可接续模型窗口和受系统隔离的工程环境。角色共享完整工具目录；权限仍由 ToolRuntime、认证主体、工作区与当前发布 Skill 核定。

## 模型窗口与证据

`ContextContinuation` 在完整工具交互边界建立不可变归档。归档保存脱敏的完整消息、原生协议块、任务/目标状态、未知写入清单及父归档引用，按主体/工作区/会话隔离并校验 SHA256。发布失败保留旧窗口，不能丢弃证据后继续。新窗口保持原始治理约束，携带最近完整工具交互及归档引用，历史细节经 `system.manage(context_index/context_read)` 回查。

输出预留、安全余量、系统提示词和完整工具定义共同计入实际模型容量。配置的输入窗口是优先接续边界；超大原始要求仍可使用实际模型容量。仅原始治理约束本身无法容纳时返回 `context_capacity_exceeded`。审批暂停另保存窗口生命周期，恢复不把审批接续提示当作新的原始要求。窗口切换不执行工具，不重放完成或结果未知的写入。

原始模型提案与实际工具交互使用不同合同：原生协议完整保存在归档，`tool_calls` 的显式列表决定发送给模型的交互；空列表表示未执行的提案。统一协议投影处理编号去重和批量编译，保留原生思考块/签名，禁止留下没有对应结果的调用。SSOT 适配与持久化恢复都保留 `None` 与空列表的区别。厂商拒绝请求时另记录仅含摘要哈希、字节数、块计数和协议违规计数的诊断，不记录提示词、思考内容或凭据，不盲目重试相同 400 请求。

## 执行环境

`DockerProjectEnvironment` 是服务端配置的执行适配器。严格工程任务只挂载生成工程，容器非 root、根目录只读、权限/进程/内存受限。它没有框架、Evaluator、宿主 HOME、凭据或 Docker Socket。项目使用内部网络，独立 broker 只允许指定依赖 registry 的 TLS 出站；预览只发布服务端指定的 loopback 端口。

Shell 与 Python 都经原有 ToolRuntime 进入同一适配器。系统隔离不可用即失败，不回退宿主 Shell；普通受信任本地执行保持原有独立合同。超时/取消清理整个任务容器及后代进程，清理未确认记录 unknown，禁止自动重试。关闭后的工作区绑定保持关闭，迟到调用不会回退宿主。跨主机 daemon 只能映射服务端明确指定的 scratch 根。

严格工程执行的 Shell/Python 默认目录统一为可写工程根目录，容器描述与结果的 `container_cwd`/`working_dir` 给出实际位置；显式 `working_dir` 仍是工作区相对路径并限定在挂载工程内。普通本地执行默认工作区根目录，`workspace.file` 始终使用工作区相对路径，不因 Shell 目录改变。服务端 assignment 明确两类工具的路径基准；文件写入越出管理根时返回 FILE_PATH_OUTSIDE_MANAGED_STORAGE、管理根与实际运行工程前缀。安全路径可附 suggested_filepath 供模型重新规划，但工具不改写参数或自动重放，准确路径仍受源码所有权约束。

运行环境描述中的 `tool_path_bases` 是路径交接的共享事实源，主运行时提示和 coding/frontend/QA assignment 使用同一份内容。exec.run 的 `working_dir_basis=workspace_root` 与 `working_dir` 描述参数；`shell_path_basis=container_cwd` 与 `container_cwd` 描述命令内部路径。容器绝对目录不能当作 working_dir 参数，省略参数仍使用已绑定工程根目录；路径拒绝不自动转换或重放。

脱敏区分宿主诊断路径与容器操作引用。正在运行的服务端 DockerProjectEnvironment 绑定允许 exec.run 输出、对应模型工具消息和原生参数归档保留容器 tmpfs 的 /tmp 路径；context_read 可取回同一引用。用户/系统消息、宿主路径、越界路径和凭据仍脱敏。权限不从模型参数或工具自报 isolation_level 推导，已关闭绑定不能获得该路径例外；此例外不赋予额外执行权限，也不允许把临时目录工程当作已整合源码。

## Coding Team

### 三种对象与候选状态机

Task 表示 worker 创建、执行、停止、报告与错误；Candidate 表示不可变源码摘要、基线、变更集、实际检查及资源闭合证据；Review 独立绑定 candidate_id/source_digest/change_digest，保存 reviewer Task 引用、裁决、实际检查、资源和有效结果。它们存储在同一主体/工作区下的独立记录中，Task 的 succeeded、文字报告或 `coding.phase` 不授予候选通过。报告持久化失败也不能抹除已封存源码和已通过的独立评审。旧 `coding.phase`、qa_subtask_id 等是兼容投影，不再作为整合依据。

| 事件/观察 | CandidateState |
| --- | --- |
| 实现源码封存且声明检查通过、资源关闭 | ready |
| 声明检查失败 | validation_failed |
| 检查结果或资源清理未确认 | execution_unknown |
| 对准确候选开始独立评审 | under_review |
| 当前评审批次所有必需 reviewer 的准确裁决与实际检查通过 | accepted |
| 当前批次存在阻断失败 / 裁决缺失 | review_rejected / review_incomplete |
| 发布开始 | publishing |
| 真实事务整合 / 冲突或未应用 / 写入未确认 | integrated / conflict / publication_unknown |

状态转换经显式事件、证据引用和 revision CAS；无效边拒绝，事件重投需同一内容。并行 reviewer 属于同一批次，一个 PASS 不覆盖另一个失败；新显式复审可形成下一批次，历史裁决完整保留。这里的批次是评审对象生命周期，不是模型调用次数或回复格式门禁。Review 终态不可修改。候选正在 publishing 或 publication_unknown 时只能从发布日志和真实文件摘要回查；不调用发布器、回滚器或重放未知源码写入。混合/外来内容仍记 unknown。

旧任务只在写入边界按准确源码与既有完整评审证据迁移；无法核实的 Task 字段不授权发布。读取不启动 worker、不写应用。新记录的主体/工作区/会话/父任务与源码身份不可替换；会话永久删除删除关联对象并留下 tombstone，晚到写入与删除共享生命周期锁，不能复活记录。

### 项目与阶段事实

Project 持久保存父目标合同引用，以及各阶段声明、依赖和 Task/Candidate/Review ID。`phase_id` 是可选归组，模型自行选择阶段与实现方式；默认每个实现一个阶段，QA 和源码修订继承目标阶段。历史候选完整保留，candidate_heads 按已封存候选的 revision_of 引用导出当前末端，阶段状态按末端候选计算。读取时从三个对象导出 working/candidates_recorded/integrated/outcome_unknown/evidence_unavailable/no_candidate，不把阶段整合推断成全部业务验收。

SSOT 注入服务端事实投影回调，每次模型请求前读取当前阶段，变化时按因果顺序追加可信的 ID/枚举/依赖事实。完整原始需求和模型历史继续保留，声明中的用户/模型文字不提升为可信指令。存储不可用明确显示 unavailable，不使用旧事实冒充当前事实，也不因此代替模型决定计划。API 与 agent.manage(get) 可读取完整阶段快照。

### 失败观察与因果边界

统一 `runtime.failure.v1` taxonomy 覆盖 Provider、工具/治理、运行时存储/上下文、应用检查/评审、资源清理和发布边界；未识别的失败记 unknown。每条含事实代码、类别、阶段与证据引用；默认 cause=unresolved。已恢复的失败尝试仍保留，已知失败不能因后续成功删除。分类只供审计与诊断，不能成为新回复次数、关键词、计划或源文件差异门禁。构建失败说明某次检查失败，未查根因前不能归咎模型能力；认证失败也不能解释其他历史构建/协议故障。历史审计保留原事实，不补造已确认归因。

`coding_agent`、`frontend_agent`、`qa_agent` 与研究/文件/数据角色共享工具目录。`coding_assignment` 声明工程、文件或目录责任、已存在的前置任务和验证命令；`.` 表示整个工程，不支持隐含 glob。服务端父任务/会话身份决定归属，模型不能覆盖它们。当前领域 Skill 不能被静默迁移到工程副本，因此这类委派要求无领域绑定的编码任务。

实现者使用独立工作区的工程副本；实现依赖消费 `integrated` 的发布结果，QA 的 review_subtask_id（包括显式 depends_on 中同一目标）消费正式 CandidateState 可评审的候选，避免“QA 等整合、整合等 QA”的循环。QA 任务不能作为发布依赖。任务完成或整合后调度已授权、同父任务和会话的等待任务；进程恢复仍通过 agent.manage(start) 启动原任务，不重复创建。依赖失败/取消会形成明确 dependency_failed 终态。QA 使用准确候选源码的独立副本，不继承实现者对话；实现者的完成声明不能代替验证。每个验证命令表示一个可执行程序和字面参数，运行结果、退出码和 QA 前后源码摘要共同决定验证状态。任意命令退出 0 仍不等于完整业务验收，独立 Evaluator 单列事实。

实现者主动结束回合时，服务端完成观察通过受治理执行入口运行 assignment 声明的检查，并绑定当前完整源码摘要。真实 failed/unknown 作为检查结果保存，同时保留模型的最终报告；不强制同一实现者再调用工具或按回复次数终止。未知结果仍优先于源码变化，停止自动执行且不能重放检查。只有检查通过、停止后代进程后源码仍一致，候选才能进入 ready（兼容投影 changes_ready）。该回调由 SubagentRuntimeControl 注入，调用者 metadata 不能伪造；候选仍须独立 QA 和真实整合。协调者依据实际检查、源码与报告决定后续工作。agent.manage(get) 回传源码文件数、字节数、模型调用及检查状态，不计算业务完成百分比。编码角色必须提供 coding_assignment，不能猜测工程位置。

编码交接从同父任务的完整用户消息保存 run_id/摘要引用，而非使用 1200 字的任务概述或只依赖协调者改写。task_state.objective_run_id 保留该目标的起始消息，后续同目标用户约束一并引用；执行时重新读取完整消息（含大消息制品）并核对摘要，缺失或改变拒绝交接。原需求作为阶段上下文，不扩展当前责任或权限。执行者同时收到初始源码路径事实；整合前父目录为空不能证明分支没有进展。取消摘要只声明 cancelled，发起来源需核对实际工具调用或外部控制记录，不能统一声称是用户取消。

独立 QA 通过原生 agent.review 工具保存 coding.qa_review.v1 裁决，最终文字回复不要求 JSON 或固定模板。工具仅允许 subagent 调用，并核对活动 QA 的服务端环境绑定和会话身份；父任务、实现者、其他会话及关闭环境不能代交裁决。QA_REVIEW_SCHEMA 与工具校验共享 scope、完整 report、blocking_findings 及 pass/fail/unknown；候选摘要与 review_subtask_id 由服务端写入，模型不能替换。非空文字或含 title/evidence 的阻断项均被保存并阻止 pass。检查成功不覆盖明确失败。缺少裁决记为 qa_incomplete，不能从自然语言猜测通过；无格式重试循环或次数门禁。实际检查未知记为 qa_unknown，并禁止重放。准确候选、有效独立通过裁决及真实检查成功仍是整合条件。为已有调用方保留完整 v1 JSON 最终回复的读取兼容，不要求新 QA 使用该表达方式。

整合前检查 QA 身份、候选摘要、责任范围和父工程当前基线。与受治理文件/执行操作共享工作区锁，并冻结项目容器的后代进程。事务先保存前后内容与 journal，再逐文件发布；中断后回查哈希，确认整合、回滚已知部分或保留 unknown。用户/其他分支已改同一文件时返回 conflict，不覆盖。这里是独立文件树副本及变更集整合，不是 Git 分支管理，也不保证任意外部编辑器绕过文件锁时的整棵目录瞬时原子性。

发布 journal 在工作区锁内保留持久化递增顺序；失败保留间隙，恢复与重复读取不分配新的已整合身份。团队验收核对每个候选的独立 QA 与真实 journal，从最初完整源码基线按发布顺序验证 before/after 链，对比最终父工程的完整源码树（包含未改动文件和路径缺失）。允许经过新一轮 QA 的连续修改，不允许未评审改写、断裂的变更链或伪造顺序。

强隔离工程进入 Coding Team 后，源码写权限属于实现分支；父任务转为协调者，QA 使用只读源码挂载。文件工具同步检查环境所有权，受治理整合仍可在锁内发布。转换只在没有正在执行的命令时进行，先暂停后代、退出写容器，再创建只读容器；失败关闭环境，不恢复写权限或回退宿主。QA/协调者允许写声明的生成目录、node_modules/.venv/.pytest_cache 与 /tmp，不能为清理删除源文件。只读角色的生成输出必须使用目录；文件型生成物可在实现分支生成，但不能作为只读角色的独立可写挂载。外部编辑器和未绑定强隔离环境的 trusted local Shell 不受这层内核挂载控制，最终完整源码树门禁仍拒绝未评审改动。

预览监听使用容器的 HOST=0.0.0.0、PORT=8080；浏览器 origin 使用各工作区独立的宿主转发端口。实现、QA 和协调者使用相同监听合同，源码读进程环境，不为切换分支改监听端口。平台只发布选定的宿主 127.0.0.1 入口。

## 模块职责

| 原入口 | 保留职责 | 独立模块 |
| --- | --- | --- |
| `query_loop.py` | 单回合状态机与兼容出口 | 模型窗口、工具准备、执行器、恢复、跟踪、审批接续、终态投影、消息序列化、工具目录 |
| `ssot_runtime.py` | 会话接入与回合生命周期 | 上下文、Provider、持久化、投影、记忆、工具身份适配 |
| `network_operations/service.py` | 工作台资源选择与协调 | 设备/连接、脚本、巡检计划/执行/生命周期、发现、基线/观测 |
| `TopologyWorkspace.tsx` | 工作台组合与视图状态 | 文档状态、保存/冲突/历史、协作、设备/区域/选区命令、版本、导航、Inspector、独立面板/对话框 |
| `NetOpsCanvas.tsx` | 单一渲染实例组合与控件 | 加载、样式、命中测试、拖拽/吸附、选择、图形投影、主题、导出 API、导航/小地图、覆盖层 |

每个入口保留现行调用合同。没有复制执行状态机，没有运行时源码拼装或 `exec` 拆文件。区域身份仍为 `canvas_items.item_id`，节点 `region_id` 引用它；主题只改变呈现，不改图纸颜色与坐标。

## 验证边界

310 轮 QueryLoop 测试使用确定性 Provider 与真实治理执行路径，验证窗口接续、完整证据和未知写入约束，不是 310 次真实 LLM 交付。真实内核隔离、真实 Provider 工程交付、独立 Evaluator 和浏览器回归分别留证。见 [编码压测](../CODING_BENCHMARKS.md)。发布和部署以用户明确授权及对应验收证据为前提；检查结束不自动授权 tag、Release 或部署。

工程源码分类由 `coding_assignment.generated_paths` 显式声明可再生输出路径（例如 `["dist"]`），默认空。`build/`、`dist/` 或嵌套同名目录本身不构成生成物身份；构建脚本属于源码。快照、QA、候选摘要、事务整合和团队验收使用同一份合同，QA 从实现任务继承且不能另行削弱。项目根、路径越界及项目配置文件不能被声明为排除输出。

子任务总生命周期与工具请求等待分开：`background=false` 最多等待 15 秒，仍在执行就返回同一任务句柄；不会因外层请求超时取消有效工作。`get/status` 查看持久化状态，`start` 仅启动前置依赖已满足的 created 任务。启动通过主体/工作区范围内的文件锁跨进程领取任务，并在锁内重读状态；首次持久化终态不可被旧工作覆盖。取消同时通过实时信号和主体/工作区范围内的持久化状态传播，跨进程可见。压测结束取消、等待并核验其全部委派分支清理，清理未知不能计为通过。

自动轮询停止属于观察者状态，不能改写生产者的 status/done/terminal。相同 running 观察可能处于正常模型/工具计算间隔，默认持续 120 秒没有新观察才暂停自动等待；真实 progress/revision/observation_token 变化重置该窗口。它不是任务执行时限，不限制持续推进的长任务。观察失败、缺失跟踪字段或轮询异常立即暂停；暂停只记录 auto_polling=stopped 与 stop_reason，子任务仍保持最近确认的生命周期。取消仍按短时间片检查。下一次显式 get/status 回查同一任务，不创建副本或接管源码。生产者给出的真实失败、完成与取消终态仍保留。

窗口续接从既有 tracking_events 投影每个工具/任务的最后观察，保存原句柄、状态、来源调用及准确回查参数，不复制轮询历史或原始工具数据。它是已观察事实而非实时状态或交付证据；模型继续回查同一任务，不因窗口更换重新委派。该投影不建立第二套任务调度器，不执行工具，不重放写入，也不绕过候选 QA 和整合合同。

### 不可变源码的构建验证

只读工程内的挂载输出目录不能支持标准构建删除整个目录。服务端将 assignment 的精确 argv 验证命令绑定到执行环境；协调者/QA 执行这些命令时使用独立、一次性的工程快照容器。复制源码摘要、已声明的输出和受范围约束的依赖缓存，构建副本允许删除/重建输出根。停止全部后代、确认清理且副本与原候选源码摘要都未改变后，只回传声明的生成目录内容，保留原挂载根。验证证据包含摘要、执行器和清理状态。任意额外命令仍使用只读源码挂载，不能将模型参数变成源码写权限；输出符号链接、源码变化或未知清理均拒绝。

依赖缓存与源码依赖分开：每个分支的 node_modules/.venv 可以为空，QA/协调者可经治理安装声明的包，不修改源码或锁文件。验证快照保留项目范围内依赖符号链接，并将绝对目标转为副本内相对链接，不能将 npm 的 .bin 链接解引用成普通文件；缓存根链接、越界或失效目标拒绝。独立 Evaluator 复用同一复制合同。

执行环境生命周期从同工作区的服务端绑定读取，调用方元数据不能伪造。QueryLoop 在请求模型前及解释返回提案前检查；已关闭环境保留结果并结束该轮，不继续对关闭容器规划工具，也不回退宿主或自动重放。探测/清理不确定则保留 unknown，由协调者核对后明确安排后续执行。

制品的秘密检测与脱敏共用完整值匹配：已脱敏的 [REDACTED]、[REDACTED_SECRET] 及其序列化结束符可以保留为证据；旁边或后缀出现真实秘密仍按原策略拒绝或脱敏。QA 的完整结果必须实际归档，归档失败的任务不能因结构化 verdict 为 pass 获得成功或整合资格。


源码提议修订使用 coding_assignment.revision_subtask_id：仅同父任务/会话、同工程、已停止且清理确认的 coding/frontend 分支可作为输入。允许完成检查明确 failed 的失败分支、检查 passed 且摘要仍匹配的未整合 changes_ready/validated 候选，或准确独立 QA 明确 fail 且 QA 也已停止、清理确认的候选；复制一个已知源码提议不要求先获得 QA 通过或强制失败结论，不构成验收或发布。终态 failed 或 cancelled 的记录都保持原事实，只有新任务显式请求修订才复制来源。新任务继承其实际源码与原 integrated 基线，保持源码责任范围，检查和生成物合同由服务端继承；来源摘要或发布基线变化会拒绝。新源码仍是未评审提议，不进入父工程，须经过新候选准确 QA 和 merge。未知结果、活动实现者、跨任务身份和 QA 角色修订被拒。原终态及源码不改写。

已通过完成检查并封存的候选，若独立 QA 仅因缺少业务证据返回 unknown、形成 qa_incomplete，可显式作为同父任务源码修订输入。服务端核对准确评审身份与摘要、实现和 QA 均已停止且清理确认，并将原 unknown 结论交接到新实现者；源候选及旧评审状态保持不变。qa_unknown 或任何实际执行未知仍拒绝修订。新候选必须重新完成准确检查和独立 QA 后才能整合；复制源码不表示补齐评审或业务验收。

修订是否有效由模型依据任务和独立 QA 判断。框架不以“必须修改源码摘要”或“必须恢复之前失败的检查”证明有效修订：检查仍绑定实际源码，同一候选也需要新的准确 QA。未修改源码不自动失败，修改源码也不自动通过。任何执行未知仍禁止自动重放。

整合入口核对准确候选、检查、独立 QA、责任范围及当前发布基线；独立团队验收回查真实 journal 与完整源码树。源码差异和检查成功都不替代业务验收；历史压测结果保留原事实。

Provider 明确返回 HTTP 402 或余额/额度耗尽时，传输和 QueryLoop 使用同一余额不足分类，返回 llm_balance_insufficient 并停止自动请求。已有工具结果及源码保留，恢复额度后才能显式继续；普通临时 HTTP 429 限流仍走恢复策略。额度不足不等于模型能力不足，也不覆盖此前实现、QA 或构建失败。

用户明确要求继续已取消的父任务时，在最近完整消息对应原 run 的条件下恢复原任务身份；其他话题或普通修改不自动恢复取消任务。该机制不复活已终止的子任务，也不重放未知写入。

受治理 exec.run 的默认 Bash 与严格容器 Bash 开启 pipefail，管道中上游失败不会被末尾 cat/tail 的 0 掩盖；命令可显式处理预期失败。原生命令解释器 Windows cmd 保持自身合同，跨平台严格工程仍运行 Linux 容器 Bash。独立检查使用原 assignment 可执行程序与字面参数，不由命令输出文案推断成功。


实现进度从服务端注入的 completion_source_digest 回调读取实际分支源码摘要，调用者不能伪造。completion_unchanged_tool_round_limit 默认 12：连续工具或输出截断轮次不改变源码时运行真实声明检查；尚未提出完成或上次通过的候选若检查失败，先向同一实现者反馈失败并给予完整纠错窗口；明确失败后再次达到窗口仍无源码变化，重验仍失败才以 completion_repair_no_progress 停止并保存分支。实际源码变化重置窗口，检查通过允许继续但不宣告业务完成。依赖安装可能使同源码通过，所以不能仅靠摘要判失败；未知检查结果终止且不重放。仅有服务端编码完成/摘要回调的实现者启用，普通绘图不受此约束，不设置工程总时长或总实现轮数。

专用编码镜像使用固定版本和摘要的 Node 22 LTS，提供同版本本地头文件及 C/C++ 工具链，npm_config_nodedir=/usr/local；原生 npm 依赖从受限包出口获取源码并在工程内编译，不要求扩大预编译产物/头文件下载权限。Node 24.21 对经典 ObjectWrap 模块的 GC 崩溃已在独立控制工程复现，不能只用 N-API 依赖安装成功判断工具链可用（[上游问题](https://github.com/nodejs/node/issues/65446)）。本机源码开发的 Node 版本要求与隔离编码镜像分开。镜像仍不包含框架、Evaluator、宿主凭据或 Docker Socket；每个环境记录实际不可变 image ID。verify_coding_isolation.py 强制原生依赖源码编译及 SQL 查询，并通过 benchmark_native_addon_probe.py 验证经典原生模块分配触发的 GC 和三次正常退出；还重复检查只读源码、受限网络、后代清理和独立验收隔离。

明确的中文同一/当前/原有任务续接不依赖汉字后的词边界；cancelled/failed 父任务只有明确 resume 才保留身份，仍核对最近完整交换与服务端 CAS。不会自动恢复终态子任务、放宽同父源码修订或重放未知写入。

容器临时目录使用有界 tmpfs（rw,exec,nosuid,nodev,512m），允许临时 QA 工程和原生编译工具加载可执行映射，其他隔离边界不变。通用原生探针在实现、只读协调及声明构建快照中实际复制、加载模块并运行 GC，不能仅用工程目录加载成功推断临时目录可用。

取消编码任务时立即关闭服务端绑定的准确分支环境并持久化清理描述，不等待模型回复。已取消任务可仅核对/清理资源，不重新执行或发布；失败清理保持未确认。压测 teardown 同时核对已取消但尚未清理的分支。后台模型请求尚未返回与容器是否已停止是不同事实，迟到模型提案仍须经过取消门禁，不能执行。

大型压测恢复额外要求 --resume-task-id，只读预检调用相同 TaskState 解析器，确认当前请求仍绑定被选择的父任务。该 ID 显式传入生产 SSOT，不再按纠错说明的语言猜测父任务；缺失或不同身份在运行前拒绝，不能将原候选改为新父任务或跨父整合。独立 RTS 编译器由固定镜像提供，应用依赖声明不承担验收器自身的编译依赖；编译与引擎始终在隔离容器，断言仍仅在可信宿主。

每个 QueryLoop 终态将尚未滚动的完整窗口保存到同一内容寻址归档，包括最后一次失败工具调用及结果、最终答复和终态原因。失败/无进展门之前先形成完整工具交互，停止后不需要额外模型请求才能保留证据。生成期间取消或撤销环境时，未执行提案单列为 not_executed 审计数据，不伪造工具结果、改变原生协议或转为可重放动作。归档失败单列 context_archive_persist_failed，保持原执行错误并拒绝虚报完整成功；不会因此重试外部写入。

制品秘密识别只认可完整的既知掩码及合法序列化分隔符。JSON 转义换行、制表符、引号和反斜杠不会将已脱敏工具证据重新分类为明文秘密；真实凭据、未知转义及掩码后的额外秘密仍被拒绝或脱敏。
