# 第二轮绘图诊断：2026-10-05

## 现场与根因

Tailscale 入口对应本机服务。“数据中心架构”原图为 18 节点、19 链路，第二轮请求为“多一点设备，太少了”。当时实际配置为 Ling-3.0-flash / openai_compatible / max_tokens=4096。首次读取图纸成功，后续响应连续出现 finish_reason=length；统一调用返回错误，却没有 output_truncated 标记，任务持续显示分析判断，原图版本未更新。

真实隔离复测确认，该模型会用完 4096 输出 token，仅返回原生推理状态，没有公开正文或完整工具调用。`_generate_with_retry` 在判断 finish_reason 之前，把它当成空响应重发，并在返回错误时丢失原生状态；`invoke_llm` 的后置截断分类因提前返回错误而不可达。QueryLoop 因而走 Provider 故障重试，无法使用已有截断续接机制。这条调用链不依赖操作系统，能够解释 Windows 同类表现；尚未取证用户 Windows 的具体回合日志。

这与此前 MiniMax 401 认证阻塞不同，也不能解释全部历史工程失败。模型输出容量触发了问题，框架对响应的分类和恢复存在缺陷；没有证据据此否定模型的完整编程或绘图能力。

## 修复

统一调用在空响应判断前识别 length / max_tokens / content_length / stream_truncated，完整返回原生状态及截断元数据，让 QueryLoop 使用既有续接。没有正文的续接提示明确说明输出容量耗尽，并要求下一次提供完整原生调用；部分工具参数不执行，不能把 JSON 跨消息拼接后当成写入。已有未知写入仍只回查，不自动重放。

提示生成位于 `loop_model.py`，状态机保留在 `query_loop.py`，满足入口模块职责预算。正常 stop 空响应、认证错误和传输错误继续使用原有分类与恢复。未修改模型、输出上限、推理功能、工具目录或图纸需求；区域身份仍为 canvas_items.item_id。
