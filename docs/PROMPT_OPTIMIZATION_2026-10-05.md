## 静态输入量

当前默认完整目录为 24 个工具；特定 Skill 的可见目录仍由原有治理决定。以同一注册表对照基线：

- 主 Agent 系统提示保持 6205 字符，约 2077 估算 token。
- 工具定义从 80338 降到 76282 字符，减少 4056 字符；估算 token 从 27696 降到 26344，减少 1352，约 4.9%。
- 逐工具对照确认只有五个编排字段的 description 改变，函数名、其余说明、所有字段、类型、必填项、枚举、默认值和嵌套约束均一致。
- 六个误触发样本分别少注入 186–352 字符的无关指导。选词仍是启发式，不能宣称完整理解所有意图。

估算使用仓库 context_budget 的字符估算法，不是 Provider tokenizer、实际账单、缓存命中或任务耗时。

## 进一步优化候选

1. **编码角色的接口协作与验收指导**：角色说明较宽泛，可进一步明确先读已整合依赖的真实导出/API，再连接界面和引擎；QA 按精确候选及需求缺口反馈。需用真实 NOC/RTS 比较接口不一致、纠错次数和完整业务覆盖，不能仅添加口号或替代运行时门禁。
2. **同一请求内的重复规则**：系统、子 Agent 通用回报说明和 profile.output_contract 重复了范围/证据/不确定性，可让 profile 只补专业产出要求。独立辅助请求仍各自需要完整规则，不能跨请求删除授权和证据边界。
3. **长工具描述的语义压缩**：工具 schema 仍是主要输入，后续应逐动作核对描述与元数据的重复，保持参数及权限、绑定、完整读取和绘图合同。不得通过截断 schema、隐藏工具或裁掉需求降低输入量。
