# 记忆：范围、权威、完整性与恢复

MemoryRecord 是记忆领域唯一事实源。按认证用户保存；global 是该用户跨项目通用记忆，workspace 必须匹配当前项目，session/task 还必须匹配服务端绑定的会话/持久任务标识。ContextStore 只是可重建投影，失效或缺失时不能代替原记录，也不能复活过期记忆。

旧记录按 schema_version 一次性迁移：原先已按用户共享的显式记忆指令和 profile 保留为 global；其他 workspace 记录归属于原项目。迁移不解释正文、不截断内容。新自然语言记忆默认当前项目；个人通用偏好可在记忆界面选择或使用结构化 scope=global。不同用户始终隔离。

## 内容和来源

| 类型 | 适合保存 | 不可冒充 |
| --- | --- | --- |
| core_rule | 用户明确偏好、纠正和稳定规则 | 助手推测的用户意图 |
| semantic_fact | 稳定身份、关系及项目事实 | 当前设备状态 |
| episodic_case | 历史观察、症状、证据、处置及结果 | 无证据根因或完整业务验收 |
| procedural_rule | 有条件的方法和核验步骤 | 无条件授权 |

记忆、知识、经验日志和基线保留各自来源。检索内容不能改变权限；原设备状态、接口、路由和告警仍属于外部证据。模型置信度和建议分数不是事实依据。

## 创建、修改与确认

API 和工具保留完整脱敏正文。memory.manage 的 create/get/search/review/update/confirm/delete/profile_get/profile_set 使用统一治理；get 返回完整记录、来源、时间、引用和替换关系，search/review 支持 offset/limit。

自然语言记住/忘记要求用户自己的指令位于输入开头；审核、翻译或文档中引用的指令不授权写入。关闭自动整理仍可明确要求记住或手动管理。自由文本规则按完整内容建立独立键，不用共同主题词判断替换。精确 supersedes_memory_id 或同域结构化 memory_key 可以表达替换；模型生成的替换进入审核流程，update 不直接覆盖生效规则；显式 confirm 是独立的受治理操作。模糊或非唯一的忘记目标不会批量删除；未指定目标时处理最近生效核心规则。

修改创建新版本。激活替换后再退役旧版本；如果退役写入中断，检索按新版本持久替换引用排除旧版本。待确认候选的修改同样保留旧记录。范围、类型和瞬时会话/任务归属必须一致，过时版本不能覆盖后续版本。跨进程文件锁保护同一用户的修改；确认后生成提案才能进入上下文。界面人工确认标为 manual_confirm；工具显式确认标为 operator_confirm，不能冒充用户亲自确认。profile_set 同样生成待审核候选，不伪造 user 来源。记忆页面可筛选范围、分类、状态，分页加载、显示历史、查看完整原文、修改并回查来源。

## 自动整理

每轮经历先保存到当前用户/项目/会话的经验日志。每批最多 12 个最早未处理事件，保留完整输入、回答和脱敏工具摘要；正常处理继续下一批直到没有积压。模型输出 JSON 操作数组，不设任意提案条数上限。

稳定事实、根因、规则、操作方法和一般模型推断保留为候选。仅 episodic_case 的 create 可以选择本批某条工具完整摘要作为原文观察：content 必须等于 quote，evidence_quote 包含准确 event_id、从零开始的 tool_index 和 quote。服务端回查实际日志并重新核对，保存带日期、工具标识和工具执行状态的观察，才允许自动生效。工具失败观察同样保留失败状态；原文核对不代表任务成功或当前环境仍成立。仅 metadata 标注 verified_tool、事件 ID 或高分均不能激活新事实。生成的停用建议也需显式确认；人工规则的自动停用请求不执行。

反思锁按实际主体与会话路径跨进程串行；提案及确定性 proposal_id 先落盘，再逐项保存结果。处理完成身份与移除批次在一次游标事务中发布。未知写入仅按稳定 memory_id 回查：查到原记录则核对并续接；未查到不自动重放。Provider 的只读生成失败保留 retry_pending，不能伪装完成。会话删除同步删除其经验日志和反思游标。

## 自动装配与历史回查

全部有效核心规则与用户 profile 独立从原记录读取，附带 ID、来源范围和更新时间，并进入每个续接窗口。知识索引故障不会删除核心规则。普通记忆先按完整可见集合排名，再在当前模型预算内选择完整记录，不固定截取三条或裁正文；未加载的排名结果明确提示，可由 memory.manage search/get 继续读取。

会话历史按身份和原始正文去重，保留公开阶段与工具事实。工作窗口容量不足时，先持久化完整原生消息归档，再以原始用户请求、核心规则、治理任务状态和归档指针续接。归档失败保留当前窗口；锚点本身超过容量则返回 context_capacity_exceeded，不静默裁约束。未知工具执行状态保留且不重放。历史截断过的旧正文不能重建。

system.manage 的 context_index 分页发现归档或列出含原文摘要的消息索引；context_search 对当前会话完整归档做中文/英文词法检索，返回可直接用于 context_read 的 checkpoint_id/message_index/char_offset/char_limit 与校验值。SQLite FTS5 为可删除重建的投影；引用每次回查原归档完整性。重复窗口中的相同消息只返回一次；指定 checkpoint 时仍可查到该窗口原文。词法检索不等于穷尽语义答案，调用方不能读取其他主体或会话，归档文字始终是脱敏历史数据。
