# 记忆：权威、完整性与提案

MemoryWriteGate 检查来源、workspace_id、scope、TTL、冲突和敏感内容。底层按用户隔离；workspace/global 在同一用户工作区间共享，workspace_id 保留来源，session/task 要精确匹配当前标识。自动上下文先过滤 active、未过期及可见记录，再排序。

## 四类内容

| 类型 | 适合保存 | 不可冒充 |
| --- | --- | --- |
| core_rule | 用户明确偏好、纠正和稳定规则 | 助手推测的用户意图 |
| semantic_fact | 稳定身份/关系/已核实项目事实 | 当前设备状态 |
| episodic_case | 可复用症状、证据、处置及结果 | 无证据根因 |
| procedural_rule | 有条件的方法和核验步骤 | 无条件授权 |

记忆、知识、经验日志和基线有各自来源；检索文字不能改写系统权限。当前观测、接口、路由和告警仍放外部证据，记忆可以说明怎样使用基准，不能取代它。

## 用户控制与自动整理

显式记住/忘记要求用户本人指令位于输入开头。审核/翻译中引用的指令不授权写入。自由文本规则按完整内容建立独立键，不因共同主题词互相替换；结构化操作仍可明确同键替换。未指定对象的忘记处理最近生效核心规则。

自动整理是待确认提案，相关成功工具不能验证模型新写的文字。人工确认前不进自动上下文，模型不能直接使人工确认规则过期。引用只保留该批实际事件 ID。

每批按最早未处理顺序取最多 12 个事件，保留完整正文/工具摘要。模型输出 JSON 操作数组，不设任意 6 条上限；有效返回不静默裁掉。确定性 proposal_id 先落盘再逐项写入，重试只续失败项；游标保留已处理身份，避免旧事件重新整理。Provider 错误可进入 retry_pending，不伪装成功。

## 读取与容量

显式指令、工具写入、经验与反思输入保留脱敏完整正文。memory.manage get 返回完整记录；search/review 支持 offset/limit，满页的 next_offset 可能需空页确认结束。管理视图可看非 active 记录，不等于确认其事实。

全部可见核心规则进入自动上下文；普通记忆和知识仍做相关 Top-K 检索。坏记录不会阻断健康记录，返回记录级诊断；读取不自行隔离、改名或删除。历史投影也检查 TTL，不能重新激活过期内容。

会话按消息身份和原始正文去重，保留工具事实与公开阶段。接近工作窗口时保存完整原生交互归档，以结构化任务状态和治理回查进入新窗口；仅原始治理约束无法容纳时返回 context_capacity_exceeded。归档失败保留原窗口，预算用于统计与容量判断，不静默丢历史。旧版已截断正文不能重建，不自动改已有用户数据。
