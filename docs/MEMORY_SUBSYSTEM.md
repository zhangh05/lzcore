# 记忆子系统

记忆是受治理的用户数据，不是模型可自由覆盖的上下文。`MemoryWriteGate` 在写入前验证 `workspace_id`、来源、scope、TTL、冲突和敏感内容。底层由当前用户身份隔离；workspace/global 记忆在同一用户的工作区间共享，workspace_id 保留为来源。session/task 记忆分别要求当前 session_id/task_id 精确匹配。自动上下文仅使用 active、未过期且范围可见的记录，先过滤再排序，避免不可见记录挤占检索名额。

```text
候选记忆 -> 脱敏与治理 -> MemoryStore
         -> user / scope / TTL 过滤
         -> UnifiedRetriever -> data_only prompt context
```

工具输出、知识命中和记忆均为证据，不能改写系统规则、工具权限或 runtime 目标。LLM 不可用或写入被拒绝时，服务端返回结构化降级原因，不泄露 provider 异常或敏感文本。

显式记忆控制要求输入以用户本人的记住/忘记指令开头。审核、翻译或解释请求中引用的指令不授权记忆写入。自由文本规则以完整内容生成独立键，不因共享“测试”“全量”等主题词互相替换；结构化管理操作仍支持明确的同键替换。未指定对象的忘记指令处理最近的生效核心规则。

自动整理的文字属于模型提案，即使引用的事件中有成功工具，也不能证明该文字已被工具验证，因此保持 pending，确认后才进入自动上下文。模型整理不能直接使用户或人工确认的规则过期。引用仅保留批次中实际存在的事件 ID。历史投影回退路径也在读取时检查 TTL，过期记录不重新进入提示词。

## 完整性与检索

显式记忆指令、工具创建/更新、经验日志和整理模型输入保留完整正文（仍执行脱敏）。`memory.manage` 的 get 动作按 memory_id 返回完整记录；search/review 返回完整命中正文，支持 offset/limit。search 满页时 next_offset 指向下一页，最后可能需要一次空页确认结束。管理工具可以查看非 active 记录，其 status 不代表事实已确认。

全部可见核心规则进入自动上下文；普通记忆和知识仍做 Top-K 检索，不等于把整个数据库塞进提示词。单条损坏或不可读的记忆记录不会阻断健康记录加载：读取结果保留记录级诊断，自动上下文明确提示存在不可读记录。读取路径不擅自改名、隔离或删除用户数据；修复/隔离是显式维护操作。

经验整理每批最多 12 个待处理事件，按最早未处理顺序读取；每个事件的正文和工具摘要完整保留。模型返回的有效操作不按前 6 项裁掉。每一批整理提案会先以确定性 proposal_id 持久化，随后逐项写入并记录结果；失败时只续跑失败项，已成功项不会重新生成或重复写入。已处理事件游标不再仅保留最后 500 个 ID，避免旧事件重新进入整理。provider 的容量或请求错误仍可能导致 retry_pending，不代表成功形成记忆。

历史版本已截断的正文无法凭空恢复；本改动不自动重写已有用户数据。

会话历史合并使用消息身份和未附加展示摘要的原文去重，保留磁盘记录中的工具事实与中间阶段。完整消息和工具结果仍保留；请求估算超过模型窗口扣除输出预留及安全余量后的容量时，运行时返回 `context_capacity_exceeded`，不裁掉历史，也不重复请求同一份超大上下文。`max_input_tokens` 等分层预算继续用于统计，不作为静默截断依据。
